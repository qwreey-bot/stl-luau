## 1. 핵심 요약 (Executive Summary)

트레이트 시스템 v4의 핵심 난제:
> "v4에서 `Stack.Of(d).Push(d, x)`는 정밀하게 검사되지만, 편한 진입점 `Stack.Push(d, x)`는 `any`이다.
> 진입점 서명을 손으로 한 번 더 적는 것은 서명이 어긋나도 못 잡으므로 원하는 답이 아니다.
> **서명을 단 한 곳에만 적고(단일 원천), 진입점과 완성 표(`Of`) 둘 다의 타입을 얻는 길이 있는가?**"

이에 대해 다양한 가설과 프로브를 실측 검증한 결론은 다음과 같습니다:

1. **v4의 "팩토리 우선" 구조에서는 진입점 타입을 자동으로 얻는 것이 수학적으로 불가능합니다. [증명 & 실측]**
   - 팩토리 함수 `function<Self, T>(of: ...) -> { Push: (Self, T) -> Self }`에서 내부의 `Push`는 이미 바깥 타입 매개변수 `Self, T`에 묶인 **비제네릭(monomorphic) 함수 타입**입니다.
   - Luau(새 솔버 포함)에는 비제네릭 함수 타입을 상위 제네릭 함수 타입 `<Self, T>(Self & Item<T>, T) -> Self`로 끌어올리는(Universal Quantification) 타입 연산자가 존재하지 않습니다.
   - `Object<F>`에서 `[string]: any` 인덱서를 제거하면 `Key 'Push' not found` 에러가 발생하며, 제네릭 인터섹션 `Object<F, E>`를 시도해도 `E`가 `unknown`으로 무너집니다 ([`probes/test_object_fe.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_object_fe.luau) [실측]).

2. **원천을 거꾸로 뒤집는 "진입점 선행(Entries-as-Source)"이 유일하고 완벽한 해법입니다. [실측 & 제안]**
   - 모노모픽 → 폴리모픽(비제네릭 → 제네릭) 승격은 불가능하지만, **폴리모픽 → 모노모픽(제네릭 → 비제네릭) 구체화는 Luau의 명시적 타입 인자 `f<<Self, T>>`를 통해 완벽하게 지원됩니다.** ([`probes/test_specialize.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_specialize.luau) [실측]).
   - 각 메서드의 제네릭 서명을 `Entries` 테이블에 **단 한 번** 정의하고, 완성 표 타입 `Stack<Self, T>`는 서명을 다시 적지 않고 `typeof(Entries.Push<<Self, T>>)`로 인스턴스화합니다.
   - **결과**: 진입점 `Stack.Push(d, 4)`는 0건, `Stack.Push(d, "wrong")`은 컴파일 에러를 정확히 포착하며, `Stack.Of(d)`와 탐침 타입 등록 검사까지 100% 정적 검사됩니다 ([`probes/probe_all_traits.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/probe_all_traits.luau) [실측]).
   - **모든 제약 조건 충족**:
     - 서명 정의: **단 1곳** (서명 불일치 위험 원천 배제).
     - `type function` 사용: **0개**.
     - 캐스트: **정의하는 쪽 단 1줄 (`:: StackObject`)만 허용, 쓰는 쪽 캐스트 0개**.
     - 런타임 비용: **0** (기존 시스템 진입점 `Entry.make` 그대로 사용).

3. **심층 발견: Luau 솔버의 추가 한계 (주의점) [실측]**
   - **Partial Generic Instantiation 솔버 버그**: 메서드 자체에 추가 제네릭이 있는 고차 함수(`Fold<Self, E, I, U>`)에서 앞의 3개 인자만 `Fold<<Self, E, I>>`로 부분 인스턴스화하려고 하면, 상류 솔버 내부 결함(`Internal error: outstanding free or blocked type in function call`)이 발생합니다 ([`probes/test_fold_generics.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_fold_generics.luau) [실측]).
   - **`& Item<T>` 반공변성 전제**: `Entries.Push<<Self, T>>`의 첫 인자 타입은 `Self & Item<T>`가 되므로, 컨테이너 타입이 `Item<T>`(`__generics`)를 구조적으로 갖추고 있어야 등록 표 대입이 성립합니다 ([`probes/test_generics_subtyping.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_generics_subtyping.luau) [실측]).

## 2. 문제 분석: 왜 팩토리 하나에서 진입점을 얻지 못하는가?

### 2.1 v4 팩토리 구조의 한계 분석

v4에서 트레이트는 다음과 같이 정의됩니다:
```luau
-- v4 정의부
const Stack = Trait.Trait("Stack", function<Self, T>(of: (Self & Item<T>) | AnyToken)
    return {
        Push = Trait.Fn<<(stack: Self, item: T) -> Self>>(),
        Pop = Trait.Fn<<(stack: Self) -> T?>>(),
        Peek = Trait.Default(...),
    }
end)
export type Stack<Self, T> = typeof(Stack.Of<<Self, T>>(nil :: any))
```

여기서 트레이트 객체의 반환 타입은:
```luau
export type Object<F> = { read Of: F, read FnTok: { [string]: number }, read [string]: any }
```

이 구조에서 발생하는 두 가지 치명적 문제는 다음과 같습니다:

1. **`read [string]: any`로 인한 진입점 타입 무력화 [실측]**:
   - `Stack.Push(d, "wrong")`을 호출해도 인덱서가 `any`이므로 타입 체커가 아무런 에러를 내지 않고 통과합니다 (`types.luau:54` 경계).
2. **인덱서 제거 시의 붕괴 [실측]**:
   - 만약 인덱서를 제거하고 `type Object<F, E> = { read Of: F } & E`를 시도하면, 호출부에서 `E`를 추론할 단서가 없어 `E`가 `unknown`이 됩니다.
   - 실행 결과: `TypeError: Type 'unknown & { ... }' does not have key 'Push'` ([`probes/test_object_fe.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_object_fe.luau) [실측]).

### 2.2 타입 이론적 증명: 왜 팩토리 F에서 Push를 꺼낼 수 없는가?

팩토리 함수 $F$의 타입:
$$F = \forall \text{Self}, T.\; (\text{of}: (\text{Self} \land \text{Item}\langle T\rangle) \mid \text{AnyToken}) \to \{ \text{Push}: (\text{stack}: \text{Self}, \text{item}: T) \to \text{Self}, \dots \}$$

진입점 `Push`가 가져야 할 타입:
$$P = \forall \text{Self}, T.\; (\text{stack}: \text{Self} \land \text{Item}\langle T\rangle, \text{item}: T) \to \text{Self}$$

- **스코프의 역전**:
  - $F$에서는 타입 변수 $\text{Self}, T$의 스코프가 **함수 $F$의 외부**에 있습니다. 따라서 반환값 안의 `Push`는 $\text{Self}, T$가 고정된 **비제네릭(monomorphic)** 함수입니다.
  - 진입점 $P$에서는 타입 변수 $\text{Self}, T$의 스코프가 **`Push` 함수 자체**에 있어야 합니다 (호출 시점 인자 추론).
- **솔버 한계**:
  - 비제네릭 함수를 제네릭 함수로 끌어올리는 연산(Universal quantification / Rank-2 polymorphism)은 Luau의 Rank-1 타입 시스템에서 지원되지 않습니다.
  - `type function`이 금지된 조건 하에서, $F$의 반환값 필드를 개별적으로 순회하여 제네릭 함수로 변환하는 메커니즘은 존재하지 않습니다.
- **결론**: **팩토리 $F$를 원천으로 두는 한, 시스템 진입점의 제네릭 타입을 컴파일러가 자동으로 합성하는 것은 불가능합니다.**

## 3. 해법 실측: 진입점 선행(Entries-as-Source) 단일 원천 설계

### 3.1 핵심 발상의 전환: 제네릭 구체화는 완벽히 지원된다!

비제네릭 → 제네릭 승격은 불가능하지만, **제네릭 → 비제네릭 구체화(Instantiation)**는 Luau 0.742에서 명시적 타입 인자 문법(`f<<Self, T>>`)을 통해 완벽하게 작동합니다.

#### [실측 검증] `probes/test_specialize.luau`
```luau
type Item<T> = { read __generics: { read Item: (T) -> T } }
type PushGeneric = <Self, T>(stack: Self & Item<T>, item: T) -> Self

local push: PushGeneric = nil :: any
local f = push<<number, number>>
local _check_f: string = f
```
**실행 명령 및 출력 [실측]**:
```bash
$ luau-analyze probes/test_specialize.luau
./probes/test_specialize.luau(9,26): TypeError: Expected this to be 'string', but got '(Item<number> & number, number) -> number'
```
`push<<number, number>>`가 정확히 `(Item<number> & number, number) -> number`로 구체화되었습니다!

### 3.2 단일 원천 아키텍처

따라서 진입점 서명을 **단 하나의 원천**으로 삼고, 완성 표 타입을 거기서 유도합니다:

```luau
-- 1. 단일 원천: 각 메서드의 서명을 '단 한 번' 적음
const StackEntries = {
	Push = Trait.Fn<< <Self, T>(stack: Self & Item<T>, item: T) -> Self >>(),
	Pop = Trait.Fn<< <Self, T>(stack: Self & Item<T>) -> T? >>(),
	Peek = Trait.Default<< <Self, T>(stack: Self & Item<T>) -> T? >>(function(ops: any)
		return function(stack: any)
			return ops.Pop(stack)
		end
	end),
}

-- 2. 완성 표 타입 유도: 서명 재작성 0회 (인스턴스화만 수행)
export type Stack<Self, T> = {
	Push: typeof(StackEntries.Push<<Self, T>>),
	Pop: typeof(StackEntries.Pop<<Self, T>>),
	Peek: typeof(StackEntries.Peek<<Self, T>>),
}

-- 3. 트레이트 객체 타입 (정의 쪽 단 1줄 캐스트)
type StackObject = typeof(StackEntries) & {
	Of: <Self, T>(of: (Self & Item<T>) | AnyToken) -> Stack<Self, T>,
	FnTok: { [string]: number },
}
const Stack: StackObject = Trait.Trait("Stack", StackEntries) :: StackObject
```

## 5. 솔버 결함 및 트레이드오프 상세 분석

새로운 설계를 도입할 때 반드시 인지해야 할 3가지 특성을 실측 근거와 함께 정리합니다.

### 5.1 Luau 솔버 결함: Partial Generic Instantiation 시 Internal Error [실측]
- **현상**: 트레이트 레벨 제네릭 `<Self, E, I>` 외에 메서드 레벨 제네릭 `<U>`가 추가로 존재하는 고차 메서드(`List.Fold`)의 경우:
  `ListEntries.Fold<<Self, E, I>>` 처럼 일부 타입 매개변수만 넘기면 상류 솔버 내부 결함이 발생합니다.
- **실측 증거** ([`probes/test_fold_generics.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_fold_generics.luau)):
  ```text
  ./probes/test_fold_generics.luau(24,14): TypeError: Internal error: outstanding free or blocked type in function call
  ```
- **대안 [제안]**: 메서드 레벨 제네릭이 있는 고차 함수는 완성 표 타입 정의 시 다음과 같이 `<U>`를 명시적으로 남겨두는 타입 표기를 권장합니다:
  ```luau
  export type List<Self, E, I> = {
      ...
      Fold: <U>(list: Self, init: U, fn: (acc: U, item: E, idx: I, ...any) -> U) -> U,
  }
  ```

### 5.2 첫 번째 매개변수 `& Item<T>`의 반공변성(Contravariance) [실측]
- **현상**: `StackEntries.Push<<Self, T>>`는 `(Self & Item<T>, T) -> Self` 타입이 됩니다.
- **의미**: 함수 매개변수는 반공변 위치이므로, 컨테이너 모듈의 구현 함수 `dequePush(self: MyDeque<T>, item: T)`가 `Item<T>`(`__generics`)를 정적으로 구현하고 있다면 완벽하게 호환 대입됩니다 ([`probes/test_generics_subtyping.luau`](file:///code/Projects/stl-luau-agy/tr3-entry/probes/test_generics_subtyping.luau) [실측]).
- **주의점**: `src/Arr.luau`처럼 아직 `__generics`가 타입 선언부에 없는 컨테이너는 탐침 등록 시 타입 불일치가 발생하므로, 컨테이너 타입에 `__generics` 마커가 반드시 선행 선언되어야 합니다.

### 5.3 식별자 모듈 스코프 제약 [실측]
- Luau의 `typeof(expr)`는 파일/모듈 스코프에 선언된 식별자만 참조할 수 있습니다.
- 따라서 `Entries` 테이블을 팩토리 함수 내부의 로컬 변수로 숨길 수 없으며, 반드시 모듈 최상단에 선언되어야 합니다.

### 최종 제안 [제안]
1. 트레이트 정의 패턴을 `Trait.Trait(name, factory)`에서 **`Entries-as-Source`** 패턴으로 전환할 것을 권장합니다.
2. 서명(인자 및 반환 타입)은 오직 `Entries` 테이블에만 단 1번 정의되며, 완성 표 타입 `Stack<Self, T>`는 `typeof(Entries.Method<<Self, T>>)`로 안전하게 유도됩니다.
3. 이를 통해 라이브러리 사용자가 가장 많이 사용하는 "편한 진입점(`Stack.Push`)"의 `any` 구멍을 완벽히 퇴치하고 stl-luau의 타입 안전성을 완성할 수 있습니다.
