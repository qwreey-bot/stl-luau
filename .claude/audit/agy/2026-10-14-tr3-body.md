## 1. 요약 및 핵심 결론

### 1.1 결론 요약
Luau 0.742 새 솔버(new solver)의 알려진 결함(업스트림 보고 초안 3번: 제네릭 함수 몸통 안에서 타입 매개변수가 구체 타입 자리에 조용히 들어감)으로 인해, stl-luau 트레이트 시제품 v4(`.claude/research/trait-v4/`)가 "정적 타입으로 검사된다"고 가정한 여러 자리가 **심각한 타입 누수(silent type leak)**에 노출되어 있음을 전수 조사로 확인했습니다 [실측].

특히 v4 README의 *"뭉텅이 구현의 몸통은 제네릭 함수로 짜서 검사됨"*, *"기본 구현은 빌더(그 종류의 완성 표를 받음)"*라는 주장은 **구조적 형상(누락된 필드, 인자 개수)만 잡을 뿐, 원소·위치·컨테이너 타입의 불일치 및 몸통 내부의 잘못된 대입/반환은 전혀 잡지 못합니다** [실측]. 더욱이 기본 구현 빌더의 타입 누수는 **트레이트 인터페이스 자체의 타입 시그니처를 오염**시켜, 잘못된 시그니처가 외부에 공개되고 정작 올바른 구현을 등록하려는 코드가 타입 에러를 맞게 됩니다 [실측].

이를 해결하기 위해, 검사를 제네릭 함수 몸통 안에서 수행하지 않고 **불투명 탐침 타입(`Trait.A`, `Trait.B`)을 사용하는 단형성(monomorphic) 함수 및 최상위 검증 한 줄**로 옮기는 패턴들을 확립하고, 7대 핵심 부정 테스트 전량(100%)을 검출함을 실측했습니다 [실측].

### 1.2 한 줄 규칙 [제안]
> **"제네릭 몸통은 형상(필드 유무·인자 개수)만 믿고, 원소·위치·옵셔널 검사는 몸통 자체를 불투명 탐침 타입(`Trait.A`)의 단형성 함수로 짜거나 최상위 탐침 줄로 확인한다."**

## 2. 솔버 결함 3번의 메커니즘과 경계 분석

실측 프로브([`probes/probe_solver_leak_rules.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_solver_leak_rules.luau), [`probes/probe_literal_opt.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_literal_opt.luau), [`probes/probe_opt_leak_details.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_opt_leak_details.luau))를 통해 규명한 Luau 0.742 새 솔버의 동작 경계는 다음과 같습니다.

### 2.1 무엇이 새는가 (진단 0건) [실측]
제네릭 함수 `function f<T>(val: T)`의 몸통 안에서는:
1. **`T <: Concrete` (서브타입 단일화 누수)**:
   - `local s: string = val` (제네릭 `T`를 구체 `string`에 대입) → **진단 0건** [실측]
   - `math.abs(val)` (제네릭 `T`를 `number`를 받는 외부 함수에 전달) → **진단 0건** [실측]
2. **`Concrete <: T` (상위타입 단일화 누수)**:
   - `local t: T = "str"` (구체 문자열을 제네릭 `T` 변수에 대입) → **진단 0건** [실측]
   - 함수 반환 서브타이핑에서 `(C, number) -> C`를 `(C, T) -> C` 자리에 대입 → **진단 0건** [실측] (반대로 `string?`을 반환하는 함수를 `T?` 반환 자리에 대입하는 것도 진단 0건)
3. **⭐ `T?` (`T | nil` 유니온)의 완전 무방비**:
   - `return "str"`을 bare `T` 반환 함수에서 돌려주는 것은 잡힙니다 (`TypeError: Expected this to be 'T', but got 'string'`).
   - 하지만 **`return "str"` 또는 `return 123`을 `T?` 반환 함수에서 돌려주는 것은 진단 0건**입니다 [실측]!
   - 컬렉션/트레이트의 핵심 메서드(`Pop: (Self) -> T?`, `Peek: (Self) -> T?`, `Get: (Self, I) -> E?`, `IndexOf: (Self, E) -> I?`, `FirstIndex: (Self) -> I?`)는 **전부 옵셔널(`T?`, `E?`, `I?`)을 반환**하므로, 몸통 안에서 구체 값을 반환하는 실수는 전멸 수준으로 새어 나갑니다.
4. **서로 다른 제네릭 간의 대입**:
   - `local u: U = val_T` (`<T, U>` 함수 안에서 `T`를 `U`에 대입) → **진단 0건** [실측].

### 2.2 무엇이 잡히는가 (정상 진단) [실측]
1. 테이블의 빠진 필드: `{ Push = d.PushBack }` (누락된 `Pop` 필드) → **TypeError 포착**
2. 인자 개수 불일치: 1개 인자를 받는 함수에 2개 인자를 넘기거나, `Pop: (C) -> T?` 자리에 `PushBack: (C, T) -> C`를 넘김 → **TypeError 포착**
3. 이미 알려진 함수 호출 자리의 직접 리터럴 인자: `st.Push(c, "literal")` → **TypeError 포착**
4. 서로 다른 제네릭 매개변수 간의 직접 교차 전달: `wrong(list, item)`에서 `I` 자리에 `item: E`를 넘길 때 → **TypeError 포착**

#### ⭐ 치명적 부작용: 트레이트 인터페이스 자체의 오염 [실측]
[`probes/probe_pinned_trait_impact.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_pinned_trait_impact.luau)에서 실측된 가장 심각한 문제는 다음과 같습니다:
- v4의 트레이트 타입 `export type List<Self, E, I> = typeof(List.Of<<Self, E, I>>(nil :: any))`는 팩토리 함수의 반환 표로부터 타입을 직접 추론합니다.
- 빌더에서 `IndexOf = Default(function(ops) return function(list: Self, item: string): I? end end)`처럼 원소를 `string`으로 못박으면, **`List<Self, E, I>.IndexOf`의 공개 시그니처 자체가 `(Self, string) -> I?`로 오염**됩니다.
- 정의 시점에서는 **에러가 0건**으로 통과합니다.
- 이후 구현자가 올바른 제네릭 구현 `(Arr<A>, A) -> number?`로 `IndexOf`를 구현하려고 하면, 오히려 `string`을 요구하는 트레이트 시그니처와 충돌하여 **구현 등록 쪽에서 컴파일 에러**가 발생합니다 (`Expected '(Arr<A>, string) -> number?' but got '(Arr<A>, A) -> number?'`).
- 반면 `Trait.Inherit`를 쓴 구현은 `Inherit`가 `any`이므로 조용히 통과하고, 런타임에 숫자 배열에 문자열을 비교하는 결함으로 이어집니다.

| 형태 A (`:: any` 단언) | 컨테이너 타입 오타 | `arrIntoStack: <T>(a: Arr<T>) -> Stack<CircularDeque<T>, T> = Stack.Of :: any` | **❌ 0건 (누수)** | 동일하게 0건 |
| 형태 B (제네릭 헬퍼 함수) | 컨테이너 불일치 | `function into<T>(a: Arr<T>): Stack<CircularDeque<T>, T> return Stack.Of(a) end` | **✅ 잡힘 (1건)** | `Expected CircularDeque, got Arr` |
| 형태 B (제네릭 헬퍼 함수) | 원소 타입 오타/못박음 | `function into<T>(a: Arr<T>): Stack<Arr<T>, string> return Stack.Of(a) end` | **❌ 0건 (누수)** | `Stack.Of(a)`의 `T`가 반환의 `string`에 조용히 단일화! |

> **소결**: `Into`를 `:: any`로 적으면 모든 실수가 새고, 제네릭 헬퍼 함수로 작성하더라도 **원소 타입 오타는 제네릭 몸통 결함으로 인해 100% 샙니다.**

## 4. 몸통 밖으로 옮기는 모양 찾기 (Patterns to Move Checking Outside)

제네릭 함수 몸통 안의 검사를 몸통 밖으로 옮겨 100% 정적 검증을 달성하는 4대 패턴을 실측 검증했습니다.

### 4.1 패턴 B (뭉텅이 구현): 탐침 타입 단형성 함수 (Monomorphic Blanket Body)
제네릭 함수 `<C, T>(Deque<C, T>): Stack<C, T>` 대신, **불투명 탐침 타입(`Trait.A`, `Trait.B`)을 사용하는 단형성(monomorphic) 함수**로 작성합니다.

```lua
-- probes/probe_monomorphic_blanket.luau
type A = Trait.A
type B = Trait.B

-- 제네릭 <C, T> 대신 탐침 타입 A, B 로 작성:
local function stackFromDeque(deque: Deque<A, B>): Stack<A, B>
    return { Push = deque.PushBack, Pop = deque.PopBack, Peek = deque.Back }
end

Trait.Blanket(Stack, { Deque }, function(deps)
    return stackFromDeque(deps[Deque])
end)
```

- **메커니즘**: `A`와 `B`는 제네릭 타입 매개변수가 아니라 독립된 구체 불투명 테이블(`{ read __probeA: true }`)입니다. 따라서 Luau 솔버 결함 3번이 전혀 트리거되지 않습니다 [실측].
- **검출력 [실측]**:
  - `Pop = function(c: A): string?` → **`TypeError: Expected 'B?', but got 'string'` 포착!**
  - `Push = function(c: A, x: number): A` → **`TypeError: Expected 'B', but got 'number'` 포착!**
  - `Pop = deque.IsEmpty` → **`TypeError: Expected 'B?', but got 'boolean'` 포착!**
  - 누락/오타/인자수 불일치 전량 포착.
- **런타임 동작 [실측]**: Lua 런타임에서 함수는 타입을 보지 않으므로, 이 단형성 함수는 임의의 컨테이너(`CircularDeque` 등)에 대해 런타임에 완벽히 정상 동작합니다 ([`probes/probe_monomorphic_blanket_runtime.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_monomorphic_blanket_runtime.luau) 실행 통과 [실측]).
- **정의자 반복 비용**: **0줄** (오히려 `<C, T>` 선언이 빠져 코드가 간결해짐).

---

### 4.2 패턴 D (기본 구현 빌더): 팩토리 밖 탐침 단형성 빌더 (Monomorphic Builder Outside Factory)
기본 구현 빌더를 제네릭 팩토리 `function<Self, E, I>` 안의 인라인 클로저로 두지 않고, **트레이트는 시그니처만 선언(`Fn`)하고 빌더는 최상위 탐침 단형성 함수로 분리**합니다.

```lua
-- probes/probe_all_patterns.luau
-- 1. 트레이트 팩토리는 순수 시그니처만 선언 (Fn)
const List = Trait.Trait("List", function<Self, E, I>(of: (Self & ItemIndex<E, I>) | AnyToken)
    return {
        Get = Trait.Fn<<(list: Self, idx: I) -> E?>>(),
        FirstIndex = Trait.Fn<<(list: Self) -> I?>>(),
        NextIndex = Trait.Fn<<(list: Self, idx: I) -> I?>>(),
        PrevIndex = Trait.Fn<<(list: Self, idx: I) -> I?>>(),
        IndexOf = Trait.Fn<<(list: Self, item: E) -> I?>>(),
        Contains = Trait.Fn<<(list: Self, item: E) -> boolean>>(),
    }
end)
export type List<Self, E, I> = typeof(List.Of<<Self, E, I>>(nil :: any))

-- 2. 기본 구현 빌더는 최상위에서 탐침 타입(A, B, C)으로 단형성 함수로 작성
type A, B, C = Trait.A, Trait.B, Trait.C
local function buildListDefaults(ops: List<A, B, C>)
    const get, firstIndex, nextIndex = ops.Get, ops.FirstIndex, ops.NextIndex
    return {
        IndexOf = function(list: A, item: B): C?
            local idx = firstIndex(list)
            while idx ~= nil do
                if get(list, idx) == item then return idx end
                idx = nextIndex(list, idx)
            end
            return nil
        end,
        Contains = function(list: A, item: B): boolean
            return ops.IndexOf(list, item) ~= nil
        end,
    }
end
Trait.Defaults(List, buildListDefaults)
```

- **메커니즘**:
  - 팩토리가 닫힌 클로저의 추론에 의존하지 않고 `Fn`으로 명확한 시그니처를 제공하므로, **트레이트 인터페이스 오염이 근천적으로 방지**됩니다.
  - 빌더 몸통 내부에서 `A, B, C`는 불투명 구체 타입이므로:
    - 원소 `item: string` 못박기 → **포착!** [실측]
    - 옵셔널 `C?`에 `123` 리터럴 반환 → **포착!** [실측]
    - `get(list, item)`처럼 인자 교차 전달 → **포착!** [실측]
- **대안 비교 (팩토리 안에 두고 최상위에서 `List<A, B, C>` 시그니처만 확인할 경우)**:
  - [`probes/probe_check_shapes.luau`](file:///code/Projects/stl-luau-agy/tr3-body/probes/probe_check_shapes.luau) 실측 결과: 팩토리 안에 빌더를 둘 경우, 시그니처에 적힌 오타(`item: string`)는 최상위 확인으로 잡을 수 있으나, **몸통 내부의 결함(`return 123` into `I?`, 로컬 구체 대입, 구체 함수 호출)은 이미 함수 내부 컴파일 시점에 삼켜져 최상위 시그니처 검사로도 잡을 수 없습니다.** 따라서 빌더 자체를 탐침 단형성 함수로 정의하는 것이 유일한 완전 해법입니다 [실측].
- **정의자 반복 비용**:
  - 트레이트 정의 시 시그니처 선언 (`Fn`) 한 번, 빌더 함수 정의 한 번.
  - 기존 v4 대비 약 3~5줄 증가. 그러나 트레이트 인터페이스 안정성과 100% 검증을 얻습니다.

### 4.3 패턴 I (중개자 Into): 최상위 탐침 한 줄 검증 (Top-level Probe Check Line)
중개자 `Into`를 성능과 런타임 제로 비용을 위해 `Stack.Of :: any`로 단언하더라도, **그 바로 아래에 탐침 타입을 대입한 1줄 검증 변수**를 둡니다.

```lua
-- probes/probe_into_shape.luau
type A = Trait.A

-- 제로 비용 중개자
const arrIntoStack: <T>(a: Arr<T>) -> Stack<Arr<T>, T> = Stack.Of :: any

-- 최상위 탐침 1줄 검증 (타입 전용):
local _: (a: Arr<A>) -> Stack<Arr<A>, A> = arrIntoStack
```

- **메커니즘**: `arrIntoStack`의 제네릭 시그니처가 `<T>(a: Arr<T>) -> Stack<Arr<T>, string>`(원소 오타)이거나 `Stack<CircularDeque<T>, T>`(컨테이너 오타)이면, 대입 줄에서 **즉시 컴파일 에러**가 발생합니다 [실측].
- **검출력 [실측]**:
  - 원소 타입 오류 (`string` vs `A`): **포착!**
  - 컨테이너 타입 오류 (`CircularDeque` vs `Arr`): **포착!**
- **정의자 반복 비용**: **정확히 1줄** (`local _: ... = arrIntoStack`). 런타임 비용 0 (미사용 지역 변수로 컴파일러 최적화 제거).

### 4.4 패턴 A (어댑터 함수): 탐침 단형성 어댑터 (Monomorphic Adapter)
컨테이너의 어댑터 헬퍼 함수(`arrPeek`)를 제네릭 함수 `<T>(ArrRead<T>): T?`로 짜지 않고, **등록 표와 동일하게 탐침 타입 `A`를 사용하는 단형성 함수**로 작성합니다.

```lua
-- probes/probe_adapter_monomorphic.luau
type A = Trait.A

-- 제네릭 <T> 대신 탐침 타입 A 로 작성:
local function arrPeek(self: ArrRead<A>): A?
    return self[self.n]
end

const arrStack: Stack<Arr<A>, A> = {
    Push = Arr.PushBack,
    Pop = Arr.PopBack,
    Peek = arrPeek,
}
```

- **메커니즘**: `arrPeek`의 몸통 안에서 `A`가 불투명 구체 타입이 되므로, 몸통 안에서 `"hello"`를 반환하거나 `number`에 대입하는 실수가 100% 컴파일 타임에 잡힙니다 [실측].
- **정의자 반복 비용**: **0줄** (제네릭 `<T>` 선언 제거).

## 6. 일반 설계 원칙 및 제안 (Recommendation)

### 6.1 일반화된 설계 원칙
1. **"제네릭 몸통은 검사기가 아니라 템플릿이다"**:
   Luau 0.742 새 솔버에서 제네릭 함수 몸통은 정적 검사가 느슨하게 풀리는 영역입니다. 구현의 타입 안전성을 보장해야 하는 라이브러리 내부 코드(뭉텅이 몸통, 기본 구현 빌더, 어댑터)는 **절대로 제네릭 함수 몸통 안에서 작성하거나 검사하려 하지 말아야 합니다.**
2. **"검사는 항상 불투명 탐침 타입의 단형성 컨텍스트에서"**:
   Luau는 런타임에 타입을 지웁니다. 따라서 컴파일 타임에 `Trait.A`, `Trait.B`라는 불투명 타입으로 단형성 함수를 만들어 검사하더라도, 런타임에는 모든 구체 컨테이너와 원소에 대해 100% 동일한 바이너리/바이트코드로 실행됩니다. **타입은 단형성 탐침으로 묶고, 런타임은 공용으로 쓰는 것**이 솔버 결함을 우회하는 가장 깔끔하고 무비용인 해법입니다.

### 6.2 v4 트레이트 시스템에 대한 구체적 제안 [제안]
1. **`Trait.Blanket`의 몸통 함수 규약**:
   - `Traits.luau`의 `stackFromDeque`, `queueFromDeque`를 제네릭 함수 `<C, T>`가 아닌 `local function stackFromDeque(deque: Deque<A, B>): Stack<A, B>`로 선언하도록 가이드/규약 변경.
2. **`Trait.Default`의 분리 (`Fn` 시그니처 + 최상위 탐침 빌더)**:
   - 트레이트 팩토리 안에서는 `IndexOf = Fn<<(list: Self, item: E) -> I?>>()`처럼 순수 시그니처만 선언하여 `List<Self, E, I>` 타입 오염을 차단.
   - 빌더는 최상위에서 `buildIndexOf(ops: List<A, B, C>)`로 작성하여 등록하도록 개선.
3. **`Into`의 1줄 검증 줄 필수화**:
   - `const arrIntoStack: <T>(a: Arr<T>) -> Stack<Arr<T>, T> = Stack.Of :: any` 바로 아래에 `local _: (a: Arr<A>) -> Stack<Arr<A>, A> = arrIntoStack`를 의무화하여 `:: any`로 인한 휴먼 에러 차단.
