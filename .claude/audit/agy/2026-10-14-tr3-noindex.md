- **기준 커밋**: `b2e09065b8fffb01ad94cfbbfd1217bfdf3c565c` (실측: `git rev-parse HEAD`)
- **검사 환경**: Luau 0.742 (`( ulimit -v 2000000; timeout 120 luau-analyze probes/*.luau )`), `./scripts/check.sh` 통과 (exit code 0)

## 1. 핵심 요약 (Executive Summary)

**과제 질문:**
> 내장 타입 함수 `index<>`·`keyof<>`도, 사용자 `type function`도 쓰지 않고 다음 두 가지를 얻는 모양이 있는가?
> 1. **기본 구현 칸의 두 보기**: 완성 표는 `F`, 등록 표는 `F?` (Inherit 불필요, 신규 기본 구현 추가 시 기존 등록 불파괴, 오버라이드 검사 유지).
> 2. **빌린 읽기 참조**: 완성 표의 쓰기 함수는 `Self & Item<T>` (읽기 전용 참조 `ArrRead` 차단), 등록 표는 `Self` 그대로 (제네릭 함수 대입 보존).

### 결론
1. **단일 팩토리 몸통 안에서 `mode: M`으로 분기하는 방식은 Luau 순수 타입 시스템에서 불가능함 ("실측")**:
   - `F | never`: Luau 새 솔버가 `F | never`를 `F`로 줄이지 못하고 호출 시 `Cannot call a value of type never in union` 에러 발생 (`probes/probe2_algebraic_limits.luau:8`).
   - 함수 오버로딩(`&`): 구체 리터럴 `"full"`/`"impl"`을 직접 넘길 때는 분기되지만, 제네릭 팩토리 함수 안에서 매개변수 `mode: M`으로 호출하면 `Calling overloaded function is ambiguous` 에러 발생 (`probes/probe3_overload_ambiguity.luau:20`).
   - Luau 새 솔버는 C++ 템플릿처럼 인스턴스화 시점에 함수 몸통을 다시 타이핑하는 것이 아니라 정의 시점에 모듈러 검사를 수행하므로, 타입 함수 없이는 단일 몸통의 타입을 조건부로 분기할 수 없습니다.

2. **단, "필수 연산의 `MutSelf` 매개변수화 + 기본 구현의 분리 선언 + 교집합(`&`) 합성" 구조를 취하면 `index<>` 0개로 동일한 두 보기를 100% 달성할 수 있음 ("실측")**:
   - `probes/probe6_refined_split.luau`에서 실측 검증 완료:
     - 등록 표: 필수 메서드 누락 검출, 잘못된 시그니처 오버라이드 차단, 기본 구현 생략 허용.
     - 완성 표: 기본 구현 non-nil 호출, 제네릭 `<U>` 보존.
     - 빌린 참조: `ArrRead`의 쓰기 호출 정적 차단.
     - 제네릭 함수 등록: `Arr.PushBack<T>` 제네릭 유니피케이션 정상 통과.
   - **대가**: 기본 구현의 옵셔널 서명을 별도 표로 1회 더 선언해야 하므로, 트레이트 정의 줄 수가 v5의 12줄에서 21줄로 9줄 증가합니다 (반복 비율 약 1.75배). 런타임 비용은 0입니다.

## 2. 왜 완성 표와 등록 표의 타입이 달라야 하는가? (문제의 본질 규명)

### 2.1 요구사항 1: 기본 구현 메서드의 타입 (`F` vs `F?`)
- **완성 표 (`Stack.Of(a)` / `Stack<Self, T>`)**: 기본 구현 메서드가 반드시 존재해야 하므로 타입이 구체 함수 `F`여야 합니다. 만약 `F?`이면 호출할 때마다 nil 체크를 강제당합니다.
- **등록 표 (`StackImpl<Self, T>`)**: 기본 구현 메서드가 옵셔널(`F?`)이어야 합니다.
  - 생략 가능: 기본 구현을 재정의하지 않아도 `missing field` 에러가 나지 않아야 함 (`v4`의 `Trait.Inherit` 표식 불필요).
  - 하위 호환: 트레이트에 새 기본 구현 메서드가 추가되어도 기존 등록 표가 깨지지 않아야 함.
  - 타입 검사: 기본 구현을 오버라이드할 때 잘못된 함수 타입을 넣으면 에러가 잡혀야 함.

### 2.2 요구사항 2: 쓰는 함수의 self 타입 (`Self & Item<T>` vs `Self`)
왜 `Mut`이 완성 보기와 등록 보기에서 반드시 달라야 하는가? 이번 탐색에서 발견한 가장 중요한 실측 결과입니다:

1. **완성 보기에서 `Self & Item<T>`가 필수인 이유 ("실측")**:
   - 소유된 컨테이너 `ArrData<T>`는 불변 팬텀 `__generics: { read Item: (T) -> T }`를 가집니다.
   - 읽기 전용으로 빌린 참조 `ArrRead<T>`는 공변 팬텀 `__readGenerics`만 있고 `__generics`가 없습니다.
   - 따라서 쓰기 메서드(`Push`)의 첫 인자가 `Self & Item<T>`여야만 `Stack.Of(r).Push(r, 1)`을 컴파일 타임에 차단할 수 있습니다 (`probes/probe4_why_mut_differs.luau:14` 실측).

2. **등록 보기에서 `Self & Item<T>`를 쓰면 깨지는 이유 ("실측")**:
   - `src/Collections/Arr.luau`의 라이브러리 함수는 제네릭 함수입니다:
     `Arr.PushBack<T>(self: ArrData<T>, item: T): Arr<T>`
   - 등록 표를 `StackImpl<Arr<A>, A>`로 선언하고 `Push = Arr.PushBack`을 대입할 때:
     - 만약 등록 표가 `Push: (Self & Item<T>, T) -> Self`라면 타겟 타입은 `(ArrData<A> & Item<A>, A) -> ArrData<A>`가 됩니다.
     - 이때 Luau 솔버는 제네릭 함수 `Arr.PushBack<T>`의 `T`를 교집합 타입 `ArrData<A> & Item<A>`로부터 유니피케이션하지 못하고 다음과 같은 타입 에러를 냅니다 (`probes/probe4_why_mut_differs.luau:22` 실측):
       ```
       TypeError: Expected this to be
           '(ArrData<A> & Item<A>, A) -> ArrData<A>'
       but got
           '<T>(ArrData<T>, T) -> ArrData<T>'
       ```
     - 반면 등록 표가 순수 `Self`(`(Self, T) -> Self`)라면 타겟 타입이 `(ArrData<A>, A) -> ArrData<A>`가 되어 `T = A`로 깔끔하게 매칭되어 통과합니다 (`probes/probe4_why_mut_differs.luau:29` 실측).

**결론:**
따라서 완성 표와 등록 표는 **수학적으로 반드시 서로 다른 타입**이어야 합니다:
- 완성 표: `{ Push: (Self & Item<T>, T) -> Self, IsEmpty: F }`
- 등록 표: `{ Push: (Self, T) -> Self, IsEmpty: F? }`

## 3. 단일 팩토리에서 `index<>` 없는 분기가 불가능한 원인 (실측 근거)

v5는 `stackDef<M>(mode: M)`라는 단일 함수 안에서 `index<{ full: F, impl: F? }, M>`과 `index<{ full: Self & Item<T>, impl: Self }, M>`을 사용해 분기했습니다.
이 `index<>`를 순수 타입 연산자로 대체하려는 시도들은 모두 실패했습니다:

### 3.1 순수 타입 대수 (유니온/인터섹션)의 한계 (`probes/probe2_algebraic_limits.luau`)
- **`F | never`**: 이론상 `F | never = F`여야 하지만, Luau 새 솔버는 유니온에 `never`가 포함되어 있으면 호출을 차단합니다 ("실측"):
  ```
  TypeError: Cannot call a value of type never in union:
    ((number) -> boolean) | never
  ```
- **바닥 함수 유니온 `F | (...any) -> ...never`**: 잘못된 인자를 넘겼을 때 에러 메시지가 심각하게 오염되며, 반환값이 `void`인 함수(`() -> ()`)와 충돌합니다 ("실측").
- **인터섹션 `&`**: $A \cap B$는 항상 $A$의 하위 타입(더 좁은 타입)이 되므로, $F$를 상위 타입인 $F?$로 넓힐 수 없습니다.

### 3.2 함수 오버로딩(`&`)의 한계 (`probes/probe3_overload_ambiguity.luau`)
- 텀 레벨에서 구체 리터럴을 넘길 때는 분기가 정상 동작합니다:
  - `Default("full", build)` -> `F` (non-nil)
  - `Default("impl", build)` -> `F?` (optional)
- 그러나 제네릭 팩토리 함수 `local function stackDef<M>(mode: M)` 안에서 호출할 경우:
  `mode`가 정의 시점에는 구체 리터럴이 아닌 제네릭 파라미터 `M`이므로 솔버가 오버로드를 결정하지 못하고 실패합니다 ("실측"):
  ```
  TypeError: Calling function (<F>("full", (any) -> F) -> F) & (<F>("impl", (any) -> F) -> F?)
    with argument pack ("full" | "impl") & M, ... is ambiguous.
  ```

### 3.3 Luau 새 솔버의 모듈러 검사 원리
Luau 새 솔버는 함수를 호출할 때마다 몸통을 새로 인스턴스화하지 않고, 함수 정의 시점에 단 한 번 몸통을 검사(Modular Type Checking)합니다.
따라서 타입 함수(`index<>` 또는 `type function`)처럼 "미해결 타입 함수식으로 식을 남겨두었다가 구체 타입 인자가 들어올 때 계산하는 기전"이 없다면, 단일 제네릭 함수 몸통 안에서 $M$에 따라 서로 다른 타입을 만들어내는 것은 원천적으로 불가능합니다 ("추정").

## 4. 실현 가능한 대안 설계: "분리 합성 패턴 (Refined Split & Intersect)"

내장 타입 함수 `index<>`를 쓰지 않고 두 보기를 완벽하게 얻을 수 있는 유일하게 건전한 방법은 **"필수 연산의 `MutSelf` 매개변수화 + 기본 구현의 분리 선언 + 교집합 합성"**입니다 (`probes/probe6_refined_split.luau`).

### 4.1 설계 코드 구조
```luau
--!strict
type Item<T> = { read __generics: { read Item: (T) -> T } }
type ItemRead<T> = { read __readGenerics: { read Item: () -> T } }
local function Fn<F>(): F return nil :: any end

-- 1. 필수 표: MutSelf를 매개변수화하여 단 1번만 선언!
local function stackReq<MutSelf, Self, T>()
	return {
		Push = Fn<<(stack: MutSelf, item: T) -> Self>>(),
		Pop = Fn<<(stack: MutSelf) -> T?>>(),
		Peek = Fn<<(stack: Self) -> T?>>(),
	}
end

-- 2. 기본 구현 런타임 본체 (완성 표용 non-nil 타입 제공)
local function stackDefaults<Self, T>()
	return {
		IsEmpty = function(s: Self): boolean return true end,
		Fold = function<U>(s: Self, init: U, fn: (U, T) -> U): U return init end,
	}
end

-- 3. 기본 구현 등록 표 (등록용 optional 타입 선언)
local function stackDefaultsOpt<Self, T>()
	return {
		IsEmpty = Fn<<((s: Self) -> boolean)?>>(),
		Fold = Fn<<(<U>(s: Self, init: U, fn: (U, T) -> U) -> U)?>>(),
	}
end

-- [완성 표]: MutSelf = Self & Item<T>, Defaults = non-nil
export type Stack<Self, T> = typeof(stackReq<<Self & Item<T>, Self, T>>()) & typeof(stackDefaults<<Self, T>>())

-- [등록 표]: MutSelf = Self, Defaults = optional
export type StackImpl<Self, T> = typeof(stackReq<<Self, Self, T>>()) & typeof(stackDefaultsOpt<<Self, T>>())
```

### 4.2 프로브 실측 결과 (`probes/probe6_refined_split.luau`)
실행 명령: `( ulimit -v 2000000; timeout 120 luau-analyze probes/probe6_refined_split.luau )`
결과:
1. `const reg: StackImpl<Arr<A>, A> = { Push = pushBack, Pop = popBack, Peek = peek }` -> **통과 (기본 구현 생략 허용)**
2. `const regOv: StackImpl<Arr<A>, A> = { ..., IsEmpty = custom }` -> **통과 (기본 구현 오버라이드 허용)**
3. `const NEG_missing` -> **Pop 누락 정확히 검출 (`missing field 'Pop'`)**
4. `const NEG_pinned` -> **string 고정 정확히 차단 (`Expected A, got string`)**
5. `const NEG_badov` -> **잘못된 오버라이드 정확히 차단 (`Expected boolean, got number`)**
6. `full.IsEmpty(a)` -> **완성 표에서 non-nil 함수로 호출 통과**
7. `fullRead.Push(r, 1)` -> **빌린 참조 `ArrRead` 쓰기 호출 정확히 차단 (`ArrRead lacks Item<number>`)**
8. canary만 에러 검출 완료.

## 5. v5 (`index<>`) vs 대안 설계 (분리 합성) 상세 비교

| 비교 항목 | 현재 v5 (`index<>` 기반) | 제안: 분리 합성 패턴 (`probe6`) |
|---|---|---|
| **내장 타입 함수 사용** | `index<{ full: F, impl: F? }, M>` 사용 | **0개 (순수 제네릭 + 교집합만 사용)** |
| **기본 구현 두 보기** | 가능 (완성: `F`, 등록: `F?`) | 가능 (완성: `F`, 등록: `F?`) |
| **빌린 읽기 참조 차단** | 가능 (`Mut<Self, T, M>`) | 가능 (`stackReq<MutSelf, ...>`) |
| **제네릭 라이브러리 함수 등록** | 가능 (`Mut = Self`) | 가능 (`MutSelf = Self`) |
| **트레이트 정의 줄 수** | **12줄** (단일 팩토리 + 모드 래퍼) | **21줄** (필수 1개 + 기본 본체 1개 + 옵셔널 서명 1개) |
| **기본 구현 서명 중복** | **1회 선언** (`Default(mode, build)`) | **2회 선언** (본체 1회 + `defaultsOpt` 1회) |
| **에러 메시지 가독성** | 타입 에러 발생 시 `index<...>`가 펼쳐져 노출됨 | **순수 테이블/함수 타입으로 에러가 깔끔함** |
| **솔버 안정성 / 리스크** | 타입 함수 관련 솔버 버그/엣지케이스 리스크 있음 | **표준 Luau 기능만 사용하여 솔버 안정성 극대화** |
| **런타임 비용** | 0 (비용 없음) | 0 (비용 없음) |

## 6. 결론 및 제안 (사용자 결정을 위한 의견)

이 보고서의 제안은 "제안"이며, 최종 결정은 사용자께서 내리십니다.

1. **타입 함수 `index<>`를 허용할 수 있는 경우 (v5 권장)**:
   - v5는 기본 구현 시그니처를 단 1번만 적어도 되므로 정의자의 반복이 최소화(12줄)됩니다.
   - Luau 새 솔버에서 `index<>`는 내장 프리미티브이므로 제네릭 `<U>` 보존이나 알고리즘 통과가 이미 실측되었습니다 (`two-views-generic.luau`).
   - 에러 메시지에 `index<...>`가 다소 노출되는 불편함만 감수할 수 있다면 생산성 면에서 가장 우수합니다.

2. **타입 함수를 엄격히 배제해야 하는 경우 (`probe6` 분리 합성 패턴 권장)**:
   - 타입 함수가 주는 컴파일러 버그 리스크나 테스트 복잡성을 원천 차단하고 싶다면 `probe6` 구조가 유일한 건전한 대안입니다.
   - 필수 연산은 `stackReq<MutSelf, ...>`로 매개변수화하여 중복이 전혀 없습니다.
   - 기본 구현의 옵셔널 서명을 별도 표(`stackDefaultsOpt`)로 한 번 더 적어야 하는 대가(9줄 증가)가 따르지만, `index<>` 없이 100% 동일한 타입 안전성을 확보할 수 있습니다.
