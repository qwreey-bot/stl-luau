## 1. 총평 및 핵심 결론

B'(모드 명시형 2-뷰 트레이트)는 v8(인라인 추론형 B)이 겪었던 **"동일 모듈 내 기본 구현 반환 검사 소멸(never 축약)" 문제를 명시적 타입 인자(`stackDef<<"full">>, stackDef<<"impl">>`)를 통해 완벽히 해결**합니다.

레드팀 공격 결과:
1. **견고한 부분**: 제네릭 알고리즘 내부 호출, 모듈 require 사슬, 순환 타입 의존성(`ops: Stack<Self, T>`), `Fold<U>` 등 자체 제네릭을 가진 기본 구현, `table.freeze` 한 줄 등록, 10개 이상의 트레이트 정의(10ms 분석 시간) 등 대다수의 복잡한 Luau 솔버 스트레스 시나리오에서 B'는 매우 안정적으로 타입을 유지했습니다.
2. **깨진 부분 (치명적 구멍 1건, 상류 결함 연계 1건, 사용자 함정 2건)**:
   - **[구멍 1] 정의부 모드 명시 누락 시 진단 0건 침묵 (치명적/현실적)**: 사용자가 `Trait("Stack", stackDef, stackDef)`처럼 `<<"full">>`, `<<"impl">>`를 누락하면, Luau 솔버가 정의부에서 에러를 전혀 내지 않고 통과시킵니다. 그러나 `M`이 미축약되어 **모든 기본 구현의 반환 타입이 조용히 `never`로 전락**하며, 이후 모든 잘못된 타입 대입이 0건으로 통과합니다 (`probe1_omit_mode_arg.luau`).
   - **[구멍 2] 오버로드 기본 구현 재정의 시 부분 구현만으로 통과 (상류 결함 연계)**: 기본 구현이 오버로드된 함수일 때, `Impl`에서는 `F?` 즉 `(A & B) | nil`이 됩니다. Luau의 유니온 내 인터섹션 서브타이핑 결함으로 인해, 재정의 시 **한쪽 갈래만 구현해도 에러 없이 등록**되어 런타임 크래시가 발생할 수 있습니다 (`probe7_overloaded_method.luau`, `probe7b_overload_subtyping.luau`).
   - **[함정 3] 작성자의 비제네릭 모드 선언 함정**: 작성자가 `<M>(mode: M)` 대신 `mode: "full" | "impl"`로 적으면, `Of` 뷰에서도 모든 기본 구현이 `nil` 가능(`?`)으로 오염됩니다 (`probe17_non_generic_mode.luau`).
   - **[함정 4] 명시적 타입 인자 누락 패딩**: `List.Of<<Self, E>>`처럼 3개 중 2개만 주면 에러 대신 나머지 슬롯이 `unknown`으로 조용히 채워집니다 (`probe22_arity_type_args.luau`).

## 2. 찾은 구멍 및 파괴 지점 (상세 분석)

### 구멍 1. 정의부 모드 인자 누락 시 진단 0건 침묵 (`never` 축약) [치명적 / 실측]

- **재현 프로브**: [probes/probe1_omit_mode_arg.luau](file:///code/Projects/stl-luau-agy/redteam/probes/probe1_omit_mode_arg.luau)
- **무게**: **치명적 (현실 발생 확률 높음)**

#### 메커니즘
B'는 사용자가 정의 시 반드시 `stackDef<<"full">>, stackDef<<"impl">>`를 적을 것을 요구합니다.
하지만 `Trait`의 시그니처가 다음과 같을 때:
```lua
local function Trait<F, G>(
    name: string,
    def: (mode: "full") -> F,
    implDef: (mode: "impl") -> G
): { read Of: F, read ImplOf: G }
```
작성자가 실수로 타입 인자를 빠뜨리고 다음과 같이 호출할 수 있습니다:
```lua
-- 실수: <<"full">>, <<"impl">> 누락
const StackMistake = Trait("Stack", stackDef, stackDef)
```
이때 Luau 솔버는:
1. `stackDef`가 `<M>(mode: M) -> ...`이므로 `(mode: "full") -> F`의 서브타입으로 판정하여 **정의부에서 0건으로 통과**합니다.
2. 그러나 `F`를 추론할 때 `M`을 `"full"`로 특수화(instantiate)하지 못하고 미축약 제네릭 `M`으로 남겨둡니다.
3. 그 결과 `Default(mode, ...)`의 반환 타입인 `index<{ full: F, impl: F? }, M>`이 축약되지 못하고 **`never`로 평가**됩니다.
4. `never`는 모든 타입의 서브타입이므로, 이후 `StackMistake.Of(a).IsEmpty(a)`를 `string`, `number`, `{ [string]: boolean }` 등 **어떤 엉뚱한 타입의 변수에 대입해도 0건으로 통과**합니다!

#### 실행 및 출력 [실측]
```bash
( ulimit -v 2000000; timeout 60 luau-analyze probes/probe1_omit_mode_arg.luau )
```
출력:
```text
./probes/probe1_omit_mode_arg.luau(42,30): TypeError: Expected this to be 'string', but got 'boolean'
./probes/probe1_omit_mode_arg.luau(44,24): TypeError: Expected this to be 'string', but got 'number'
```
- `StackCorrect`를 사용한 42번 줄(`correct_bad1: string = StackCorrect.Of(a).IsEmpty(a)`)은 정확히 `Expected this to be 'string', but got 'boolean'`을 잡았습니다.
- **반면 `StackMistake`를 사용한 36~38번 줄(`bad1: string`, `bad2: number`, `bad3: table`)은 에러가 0건으로 완전히 침묵했습니다.**

#### 대책 및 제안 [제안]
외부 기여자나 사용자가 B' 방식으로 새 트레이트를 만들 때 흔히 겪을 수 있는 침묵 구멍입니다. `Trait` 정의 줄에 대한 린트 검사(정의 함수 전달 시 `<<"full">>` 및 `<<"impl">>` 필수 포함 여부 정규식 검사)를 CI에 포함하거나, 템플릿 코드 매크로를 제공해야 합니다.

### 구멍 2. 오버로드된 기본 구현 재정의 시 부분 구현 허용 [상류 결함 연계 / 실측]

- **재현 프로브**: 
  - [probes/probe7_overloaded_method.luau](file:///code/Projects/stl-luau-agy/redteam/probes/probe7_overloaded_method.luau)
  - [probes/probe7b_overload_subtyping.luau](file:///code/Projects/stl-luau-agy/redteam/probes/probe7b_overload_subtyping.luau)
  - [probes/test_union_intersection.luau](file:///code/Projects/stl-luau-agy/redteam/probes/test_union_intersection.luau)
- **무게**: **중간 / 상류 의존**

#### 메커니즘
트레이트 기본 구현이 오버로드된 함수(`OverloadFn = ((x: number) -> number) & ((x: string) -> string)`)인 경우:
B'에서 `mode = "impl"`일 때 `index<{ full: F, impl: F? }, "impl">`에 의해 해당 필드의 타입은 `OverloadFn?` 즉 `OverloadFn | nil`이 됩니다.

Luau 타입 검사기(0.742)에서:
1. `OverloadFn` 단독 타입에 `(number) -> number`를 대입하면: `string` 갈래가 빠졌음을 인지하고 정상적으로 타입 에러를 냅니다 (`probe7b` 8행).
2. **그러나 `OverloadFn | nil` (즉 `OverloadFn?`) 유니온 타입에 `(number) -> number`를 대입하면**: Luau가 서브타이핑을 완화하여 **에러 없이 통과**시킵니다 (`probe7b` 11행, 15행, `test_union_intersection` 5~6행).
3. 결과적으로 `StackImpl` 등록 표에서 오버로드된 기본 구현을 재정의할 때, 구현자가 `number` 처리 갈래만 만들고 `string` 처리 갈래를 완전히 빠뜨려도 컴파일 타임에 0건으로 통과하며, 런타임에 `string`으로 호출 시 런타임 에러가 발생합니다.

#### 실행 및 출력 [실측]
`probes/test_union_intersection.luau`:
```lua
type Overload = ((number) -> number) & ((string) -> string)
type Target = Overload | nil

local bad: Target = function(x: number): number return x end -- 0건 통과! (string 갈래 누락)
local bad_str: Target = function(x: string): string return x end -- 0건 통과! (number 갈래 누락)
local bad_bool: Target = function(x: boolean): boolean return x end -- 에러 검출!
```
```bash
( ulimit -v 2000000; timeout 60 luau-analyze probes/test_union_intersection.luau )
```
출력:
```text
./probes/test_union_intersection.luau(7,26): TypeError: Expected this to be
	'(((number) -> number) & ((string) -> string))?'
but got
	'(boolean) -> boolean'
```
- `(boolean) -> boolean`만 거절되고, 오버로드의 부분 갈래인 `bad`, `bad_str`는 둘 다 0건으로 침묵 통과했습니다.

#### 대책 및 제안 [제안]
트레이트 기본 구현에는 되도록 함수 오버로드(`&`)를 사용하지 않고 개별 이름의 함수로 분리하거나 제네릭 함수를 사용하는 것이 권장됩니다.

### 구멍 3. 작성자가 `<M>(mode: M)` 대신 `(mode: "full" | "impl")`로 적을 때의 함정 [실측]

- **재현 프로브**: [probes/probe17_non_generic_mode.luau](file:///code/Projects/stl-luau-agy/redteam/probes/probe17_non_generic_mode.luau)
- **무게**: **중간 (외부 작성자 혼란)**

#### 메커니즘
외부 개발자가 B' 패턴을 볼 때 "mode는 'full' 아니면 'impl'인데 왜 굳이 제네릭 `<M>(mode: M)`으로 선언하지?"라고 생각하고 `local function stackDef(mode: "full" | "impl")`로 작성하는 실수를 할 수 있습니다.

이 경우:
1. `Default`의 인자로 `mode`("full" | "impl")가 전달되면, `index<{ full: F, impl: F? }, "full" | "impl">`가 됩니다.
2. 유니온 키 인덱싱은 각 갈래 결과의 합집합이 되므로 `F | F?` = `F?`가 됩니다.
3. 따라서 **완성 표인 `Stack.Of` 뷰에서조차 기본 구현 메서드가 선택적(`?`) 타입이 되어버립니다.**
4. 모든 소비자는 `ops.IsEmpty(s)`를 호출할 때마다 `"Value of type could be nil"` 에러를 마주치게 됩니다.

#### 실행 및 출력 [실측]
```bash
( ulimit -v 2000000; timeout 60 luau-analyze probes/probe17_non_generic_mode.luau )
```
출력:
```text
./probes/probe17_non_generic_mode.luau(40,20): TypeError: Value of type '((Arr<number>) -> boolean)?' could be nil
```

### 구멍 4. 명시적 타입 인자 아리티 부족 시 `unknown` 자동 패딩 [실측]

- **재현 프로브**: [probes/probe22_arity_type_args.luau](file:///code/Projects/stl-luau-agy/redteam/probes/probe22_arity_type_args.luau)
- **무게**: **중간 (Luau 솔버 특성)**

#### 메커니즘
`List.Of`가 `<Self, E, I>` 3개의 제네릭 매개변수를 받을 때:
- 4개를 넘기면 (`<<Arr<string>, string, number, boolean>>`): Luau가 `Too many type parameters passed` 에러를 냅니다.
- **그러나 2개만 넘기면 (`<<Arr<string>, string>>`)**: Luau가 에러를 내지 않고 **나머지 3번째 인자 `I`를 조용히 `unknown`으로 채웁니다.**
- 그 결과 `List.Of(ARR).Get(a, idx)`에서 `idx`가 `unknown`이 되어, 어떤 타입의 키를 넘겨도 검사 없이 통과하게 됩니다.

## 4. B'의 구조적 비용 및 사용자 인간공학(Ergonomics) 분석

B'가 기술적으로 대부분의 타입 구멍을 막아내지만, 실제 라이브러리 개발자 및 사용자 관점에서는 다음과 같은 구조적 비용이 존재합니다:

1. **기본 구현이 없는 순수 트레이트의 보일러플레이트 강제 ([실측: `probe18_trait_without_defaults.luau`])**:
   - `Deque`, `Queue`처럼 모든 메서드가 필수인 트레이트조차도 `Trait` 함수의 시그니처(`(mode: "full") -> F`)를 맞추기 위해 의미 없는 `local function dequeDef<M>(mode: M)` 2중 클로저를 작성하고 `dequeDef<<"full">>, dequeDef<<"impl">>`를 넘겨야 합니다.
   - 단일 팩토리 `function<Self, T>(of)`를 바로 넘기려 하면 타입 에러가 발생합니다.
2. **복제된 타입 시그니처와 템플릿 복잡도**:
   - 트레이트 하나를 정의할 때마다:
     1. 외부 팩토리 `def<M>(mode: M)`
     2. 내부 팩토리 `<Self, ...>(of: ...)`
     3. 트레이트 객체 `Trait(name, def<<"full">>, def<<"impl">>)`
     4. 완성 타입 `type Trait<...> = typeof(Trait.Of<<...>>(nil :: any))`
     5. 등록 타입 `type TraitImpl<...> = typeof(Trait.ImplOf<<...>>(nil :: any))`
     총 5개의 구성 요소를 정확한 규격으로 작성해야 합니다.
3. **후보 C(두 표 분리) 대비 트레이드오프**:
   - 후보 C(타입 함수 0, 필수 표/기본 표 분리)는 `index<>` 타입 함수가 전혀 없으므로 `never` 축약 위험이 원천 차단되지만, 기본 구현 필드 이름을 교집합 타입 정의 시 두 번 반복해야 하는 번거로움이 있습니다.
   - B'는 기본 구현 필드 이름을 한 번만 적을 수 있는 대신, `index<>` 타입 함수와 모드 명시(`<<"full">>`)라는 Luau 고급 트릭에 의존합니다.

## 5. 결론 및 최종 제안

1. **B' 채택 여부**:
   - v8의 인라인 모드 추론 구멍(`never` 축약)을 해결한 B'는 **타입 시스템의 표현력, 검증 엄밀성, 컴파일 속도(10ms) 측면에서 매우 우수한 설계**입니다.
   - 따라서 **채택을 권장**합니다.
2. **반드시 보완해야 할 점 (제안)**:
   - **CI 가드 추가**: `Trait.Trait("...", ...)` 호출부에서 둘째/셋째 인자가 `<<"full">>` 및 `<<"impl">>`로 명시적으로 인스턴스화되었는지 정규식 또는 AST 린트로 검사해야 합니다. (누락 시 구멍 1의 `never` 침묵이 발생하기 때문)
   - **기본 구현 오버로드 금지 규칙**: 기본 구현에는 함수 오버로드(`&`)를 사용하지 않고 제네릭 또는 개별 이름 함수를 사용하는 컨벤션을 `conventions.md`에 명시해야 합니다. (구멍 2 방지)
   - **기본 구현 없는 트레이트를 위한 편의 오버로드 고려**: 기본 구현이 없는 트레이트는 단일 팩토리 `Trait.Pure("Deque", dequeDef)` 형태로 등록할 수 있는 별도 생성자를 제공하면 모드 보일러플레이트를 줄일 수 있습니다.
