### 6. 번지는 다시 짓기에서 난 겹침 (p02 (c))
`Stack.ImplWhere({ MyRing })` 을 먼저 걸고 나중에 `Deque.ImplWhere({ MyRing })` → Stack 이 `{Deque}`·`{MyRing}` 두 뭉텅이로 겹침:
```
Deque.ImplWhere({MyRing}) — Stack 이 두 뭉텅이로 겹침	false	./p02-later-rebuild-blame.luau:65: Trait: two blanket implementations of Stack apply to P02.Ring1 — …
실패한 뒤: Deque 구현? r1	true	r2	false
실패한 뒤: Queue 구현? r1	false	r2	false
권하는 길을 따른 뒤 Deque.ImplWhere({MyRing}) 다시	false	./p02-…:76: Trait: two blanket implementations of Deque apply to P02.Ring1 — …
```
선검사는 그 트레이트 자신만 봐서, 기록한 **뒤** 위로 번지는 `refresh(Stack)` 에서 납니다. 명시 등록도 같음(8절 (4) 의 `W2.ImplFor` 가 실패한 뒤에도 W2 는
기록돼 있어 다시 하면 "already implements"). 제안: 기록 전에 builder 를 부르지 않는 순수 검사(표를 갖게 될 트레이트 집합을 dependents 로 닫아 가며
뭉텅이 수를 셈), 아니면 문서에 이 예외를 적기.

### 7. 다이아몬드의 다시 짓기 횟수 (p05, -O2)
층 4: builder 60회 / 층 8: 1020회 / 층 12: 16380회 0.008s / 층 16: 262140회 0.119s. `commit` 이 dependents 를 깊이 우선으로 바로 다시 지어 다이아몬드마다
위층이 두 번. 고친다면 토큰 하나에 대해 위상 순서로 한 번씩.
