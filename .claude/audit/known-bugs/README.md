```bash
luau .claude/audit/known-bugs/repro.luau
```

**지금은 5건 실패가 정상입니다** — 아직 안 고쳤기 때문입니다. 3단계
(`src/Arr.luau` 재작성)에서 이 파일이 **0 실패**가 되어야 합니다.

## 버그 1 — `slice` 의 `to_start` 삽입 경로 (1건)

`to` 와 `to_start` 를 둘 다 주면 기존 원소를 밀어내려고
`table.move(to, to_len - to_start + 1, to_len, to_start + move_len)` 을
부르는데 **소스 구간이 틀렸습니다.**

`to_len = 5, to_start = 2, move_len = 2` 일 때 2..5 를 4..7 로 옮겨야 하는데
4..5 만 옮깁니다. 실제 결과:

```
got  [9,1,2,9,9,nil,nil] n=7     ← 꼬리 원소 둘을 잃음
want [9,1,2,9,9,9,9]     n=7
```

`to.n = to_len + move_len` 도 중간 삽입을 고려하지 않습니다.

**고치기 전에 `to_start` 의 의미를 정해야 합니다** — 밀어내고 삽입인지
덮어쓰기인지. 2026-08-31 에 추가한 `Reverse` 는 같은 시그니처인데 **덮어쓰기**
로 구현돼 테스트로 고정돼 있어 지금 둘이 어긋나 있습니다. 위 재현은
"밀어내고 삽입" 을 가정한 것이라, 덮어쓰기로 정하면 기대값을 바꿔야 합니다.

## 버그 2 — `nil` 구멍에서 `Max`/`Min`/`Sum`/`Prod` (4건)

`1..n` 사이에 구멍이 있으면 `compareTo(nil, base)` 가 `nil - base` 로 터집니다.
`Sorted` 는 2026-08-31 에 구멍을 걸러내도록 고쳤지만 이 넷은 그대로입니다.

컨테이너 전반에서 구멍을 어떻게 다룰지 한 번에 정할 문제입니다.

## 대조군 (3건, 지금도 통과해야 함)

이미 고친 것들이 회귀하지 않았는지 봅니다: `Clear` 후 `is_arr`,
`EraseInplace(3, 1)` 가 no-op, `Sorted` 가 구멍에서 안 터짐.
