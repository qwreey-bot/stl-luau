# 관례와 작업 방식

`CLAUDE.md`가 `@import`하므로 매 세션 로드됩니다 — 세션마다 필요하진 않은
상세는 `.claude/base/`나 개별 문서로.

## 언어 관례

- 사용자는 한국 유저입니다. 사용자가 보는 것(대화, plan, `.claude/` 문서,
  커밋 메시지 요약 등)은 한국어로. 코드 안 주석은 기존 파일들처럼 한국어로
  쓰는 게 이 저장소의 지배적인 스타일입니다(`src/Arr.luau` 참고) — 다만
  강제는 아니고, 기존 파일을 고칠 땐 그 파일의 기존 언어를 따르세요.
- 에러 메시지 문자열, 함수/변수 식별자는 영어.

## 코드 스타일

**[2026-09-22 전면 재작성 후 기준]** 확정 근거는 `.claude/base/rewrite-plan.md`
1-5 / 1-6 절. 아래와 다른 옛 코드는 더 이상 저장소에 없습니다.

- **네이밍**: 기준은 *"값을 만들거나 감싸는 것은 대문자, 판별 술어와 지역
  변수는 소문자."*

  | 무엇 | 케이싱 | 예 |
  |---|---|---|
  | 타입 | PascalCase | `Arr<T>`, `ArrView<T>`, `HashMapData<K, V>` |
  | 생성자 | PascalCase | `Arr.Of`, `TreeMap.New`, `Heap.FromList` |
  | 연산(네임스페이스 함수) | PascalCase | `Arr.PushBack(a, v)`, `Arr.SortInplace(a)` |
  | 술어 | camelCase, 최상위 | `stl.isArr(v)`, `stl.isHeap(v)` |
  | 지역 변수 | camelCase | `arrLen`, `moveLen`, `outLen` |
  | `require` 받은 모듈 | PascalCase | `local Common = require("./Common")` |
  | 소스 파일 | PascalCase | `src/Arr.luau`, `src/HashSet.luau` |
  | 테스트 파일 | 소문자 + dot | `tests/spec.arr.luau` |

- ⭐ **데이터는 엔티티, 함수는 서비스** (2026-10-01 사용자 결정, 질문 AB —
  예외 없음, `Fut` 포함). 컨테이너는 **메타테이블 없는 평범한 테이블**이고,
  모든 연산은 모듈의 **네임스페이스 함수**입니다(`Arr.Map(a, fn)`,
  `Fut.AndThen(f, fn)`). **콜론 메소드는 없습니다.** Luau 표준 라이브러리
  (`table`/`buffer`/`coroutine`)와 같은 모양입니다. 근거:
  - **속도**: 메타테이블이 있으면 `t[i]` 에 1.59배 세금 — 걷어내니 `Arr` 원소
    작업이 0.57~0.83배(perf 16절). fastcall 은 사용자 라이브러리에 안 먹지만
    인덱싱 세금은 먹습니다.
  - **일관성**: `Optional`(태그 유니온)은 메소드를 가질 수 없어(`spikes/45`)
    콜론으로는 전 모듈을 덮을 수 없었습니다.
  - **타입**: 함수가 타입 **바깥**에 있으니 전체형이 데이터부 그 자체
    (`Arr<T> = ArrData<T>`). 예전의 메소드 교집합·재귀 별칭 우회(`typeof`
    나열)·"계약 멤버 재선언 금지" 규칙이 전부 필요 없어졌습니다.
  - **확장**: `Arr<T>` 를 받는 함수는 누구나 같은 모양으로 더합니다(사용자:
    *"라이브러리에 묶여 무언가 더 넣기 어려워지는게 원천적으로 해결"*).
  - **쓰는 맛**: 체이닝은 없고 문장으로 나눠 씁니다 — *"quad 는 expr 공간에
    놓이는 연산들이라 원라이너가 필요했고, 여기는 속도가 더 생명"*. 생태계
    대조(외부자 검토)도 컨테이너·데이터 처리는 바깥 함수가 강하게 우세.

- **모듈 패턴**: 이름 붙은 top-level 함수들(첫 인자가 데이터) + **순수 테이블
  네임스페이스** `return { … }` + 판별용 **태그 필드**(`__arr__`, `__hashmap__`
  …). 태그는 세 겹으로 씁니다(M0 리뷰):
  - **런타임**: 생성자가 붙이는 실제 필드. **모든 생성·반환 경로**가 붙여야
    합니다(`spec.contracts` 5절이 전수로 지킴).
  - **술어**: 태그 **와 모양**을 같이 봅니다 — 태그는 공개 문자열이라 위조할 수
    있습니다(`{ __fut__ = true }` 를 `Fut.Chain` 이 입양해 `AwaitSafe` 가 던졌음).
    태그 키는 **라이브러리 예약어**입니다.
  - **타입**: 데이터부에 `read __arr__: true` 같은 **팬텀 태그** — 생성자를 거치지
    않은 리터럴(`{ n = 3 }`)이 컨테이너 자리에 들어가는 것을 막습니다(`spikes/53`).
    **읽기 전용 self(`ArrRead`)에도** 둡니다 — 없으면 리터럴·`table.pack` 결과·
    콜백 뷰가 `CompactInplace` 를 거쳐 `Arr` 로 둔갑했습니다(M0 2라운드).
    술어는 모양 조건을 **하나씩 뺀 위조**까지 대조합니다(`spec.contracts` 6절).
  - **위조의 경계**(M0 4라운드, 제가 정함 — 되돌리기 쉬움): 술어는 **태그 +
    최상위 필드 전부의 타입**(함수 필드 포함, 셋은 안쪽 맵을 맵의 술어로)까지
    봅니다. 그보다 깊은 불변식(크기가 데이터와 맞는지, 정렬, 거대한 `n`)까지
    갖춘 위조는 **계약 밖**입니다 — 태그 키는 예약어입니다. 리뷰도 이 경계 밖의
    위조는 한계로 분류합니다. (라운드마다 한 겹씩 깊은 위조가 나와 경계를 그음.)
  - 대가: 태그 필드가 데이터에 드러납니다 — `pairs` 순회·깊은 비교·직렬화에서
    키가 하나 더 보입니다(`Arr` 는 원래부터). 콜러블 네임스페이스(`Arr(...)`)는
  **쓰지 않습니다** — 제네릭 생성자가 `__call` 경유에서 타입 인자를 잃고 모듈
  오타도 못 잡습니다(실측). `src/Arr.luau` 가 정석입니다.

- **타입**: 데이터부(`XxxData`) = 전체형(`Xxx`). 콜백이 셋째 인자로 받는
  `ArrView<T>` 는 읽기 전용 평범한 테이블입니다. 자세한 것은
  `.claude/base/typing-limits.md`.

- **함수의 첫 인자는 데이터부(`XxxData<T>`)로 받습니다.** 원소가 유니온일 때
  (`Arr<number?>`)도 추론이 서는지는 `spikes/46` 이 지킵니다. 자기 자신을
  돌려줄 땐 `return self :: any`. (예전엔 전체형에 섞인 계약 조각 때문에 이게
  **필수**였습니다 — 지금은 전체형이 곧 데이터부라 같은 뜻입니다.)

- **계약은 함수 묶음입니다**(`Types.ListOps<C, E, I>` 등). 필드는 **`read`** —
  그래야 모듈 테이블(제네릭 함수들)이 그대로 구현체로 들어갑니다(실측).
  공용 알고리즘은 `(ops, 컨테이너, …)`: `Algorithm.IndexOf(Arr, a, x)`.
  ⚠️ 계약을 받는 제네릭 함수는 원소 타입을 함수 묶음에서도 끌어오며 `unknown`
  이 섞이니 **타입 인자를 명시**하세요(`fillAndCount<<H, number>>(HashMap, m, 1)`).

- **제네릭이 안 풀릴 땐 명시적 타입 인자** `f<<T>>(...)` 를 씁니다 —
  `Arr.Of<<number>>()`, `HashMap.New<<string, number>>()`,
  `nested:Flat<<number>>()`. 캐스트(`:: Arr<number>`)는 차선입니다.
  캐스트는 "내 말을 믿어라" 이고 이건 "답을 알려준다" 입니다.
  ⚠️ 다만 **콜백 파라미터 주석은 이걸로 안 없어집니다** — 그건 다른 한계이고
  지금도 주석을 답니다. 자세한 것은 `base/typing-limits.md`.

- **`const` 바인딩**: 재대입 없는 바인딩은 `const`. ⚠️ **`const` 는 `local`
  을 대체하는 키워드입니다**(`const x = 1`). `local const x = 1` 이라고 쓰면
  `const` 라는 지역변수를 만들고 `x = 1` 은 **전역 대입**이 됩니다 — 타입
  주석이 없으면 문법 에러도 안 납니다.

- **삼항 `and/or` 금지.** `if-then-else` 표현식만. 단순 2항 `x or y` 는 허용.

- **`--!strict` 를 모든 파일 1행에.** 그 다음 `--[[ Module — 설명 ]]` 블록.
  예외는 없습니다(`--!nocheck` 이던 `Tuple`/`TypeUtil` 은 내렸습니다).

- **탭 들여쓰기.** 주석은 한국어, 식별자와 에러 메시지는 영어
  (`error("Arr: Range step must not be zero")` 형식).

- **배열 표현**: `{ n: number, [number]: T }` + 태그 필드(`__arr__`).
  Lua 기본 `#` 대신 `self.n` 을 신뢰합니다 — 희소 배열과 꼬리 `nil` 문제를
  피하기 위함입니다. 1..n 사이에 구멍이 있을 수 있고, **각 함수가 구멍을
  어떻게 다루는지 주석에 적습니다.**
  ⭐ **구멍은 타입에 `T?` 로 드러냅니다**(2026-09-30 사용자 결정, 질문 T —
  Rust `MaybeUninit` 과 같은 결: 기본값이 없어 대신 채워줄 수 없으니 드러내는
  게 가장 명시적). 구멍이 생길 수 있는 생성자는 `Arr<T?>` 를 돌려주거나
  명시를 요구합니다(`Sized(n, fill)` 의 `fill` 필수, 구멍을 원하면
  `Arr.Sized<<number?>>(n, nil)`). 그래서 **콜백 계열**(`Map`/`Filter`/`Fold`/
  `Count`/`Find`/`Some`/`Every`/`Reduce` …)이 구멍을 **`nil` 그대로 넘기는
  것**이 건전하고, **집계·정렬**(`Sum`/`Prod`/`Max`/`Min`/`Sort`/`Join`)이
  구멍을 건너뛰는 것은 타입이 거짓말할 때(캐스트, `a[i] = nil`)를 위한
  **런타임 그물**입니다. `?` 를 떼는 길은 `Compact`/`FillHoles`(새 배열).
  ⚠️ 그래서 **콜백 타입의 다른 인자에 `T` 를 넣지 않습니다** — 셋째 인자가
  `ArrView<T>` 이던 때는 네임스페이스 호출에서 콜백 원소를 더 좁게 적은 것
  (`number?` 자리에 `v: number`)이 안 잡혔습니다. 지금은 **`ArrView<unknown>`**
  (질문 V → Z: `any` 로 뺐더니 `any` 가 콜백 반환을 타고 결과 타입으로
  샜습니다. `base/typing-limits.md`).

- **리스트를 받는 진입점의 길이 규약**: `{ T }` 를 받는 함수(`FromList`,
  `FromRecords`, `CloneFromTable` …)는 **`Common.listLength`**(`n` 이 0 이상의
  정수면 그것, 아니면 `#`)로 길이를 재고 숫자 루프로 돕니다 — `#`/`pairs` 로
  읽으면 `Arr` 의 `n`·태그 키까지 원소가 되거나 구멍 뒤를 잃었습니다(M0 3라운드).
  구멍을 건너뛴 조밀한 사본이 필요하면 `Common.denseList`.
  ⚠️ `n` 이 없으면 **`#` 규칙**입니다 — `t[1] = 10; t[3] = 30` 처럼 대입으로 만든
  구멍 든 테이블은 `#` 가 경계 중 아무 곳이나 돌려줘 뒤가 잘릴 수 있습니다(Lua
  규격, `table.insert`/`table.concat` 과 같음). 예전엔 일부 진입점이 `pairs` 로 돌아
  우연히 다 읽었지만, 그건 `n`·태그 같은 문자열 키까지 원소로 담는 대가였습니다.
  구멍이 있을 수 있으면 `table.pack`/`Arr` 처럼 **길이를 아는 경로**로 넘기세요.

- **맵/셋 표현**: `{ data, size }` 래퍼. 인스턴스에 길이 필드를 직접 두면
  `HashMap<string, …>` 에서 `Set("size", v)` 가 그걸 덮어씁니다.

- **`Inplace` 접미사 쌍**: 새 컨테이너를 만드는 판과 자기를 변형하는 판을
  쌍으로 둡니다(`Sort`/`SortInplace`, `Reverse`/`ReverseInplace`). 둘 다
  필요하지 않다면 왜 아닌지 명확히 하세요.
  ⚠️ **타입을 바꾸는 `*Inplace` 는 입력을 소비합니다**(2026-10-01 사용자 결정,
  질문 Y): `MapInplace`/`FlatmapInplace`/`FlatInplace`/`CompactInplace` 는 같은
  테이블을 다른 원소 타입으로 돌려주므로 **결과만 쓰고 원래 변수는 다시 쓰지
  않습니다**(Rust 의 move — Luau 는 강제 못 함, 주석으로). `T → T` 로 막는 안은
  *"Map 이란 이름에 부합하지 않게 됨"* 으로 접었습니다. 반대로 **입력으로 `T`
  를 받는** 제자리 판은 조용히 `T` 가 넓어지므로 불변으로 막습니다
  (`FillHolesInplace`, 질문 U) — 차이는 "타입 변화가 호출에 드러나는가" 입니다.

- **구간 규약**: 닫힌 구간 `[start, last]`, 음수 인덱스 지원, 범위를 넘으면
  clamp, 뒤집힌 구간은 조용히 빈 결과 — `string.sub` 와 같습니다.

- ⭐ **숫자 인자 정책** (2026-09-30, 리뷰 네 라운드가 함수마다 하나씩 찾아서
  굳힘): 위치·구간·k·shift·길이 같은 **인자로서의 숫자**는
  - **NaN 은 에러**이고, 에러는 **사용자 호출 줄**을 가리킵니다 — 아래 "에러 규약".
  - 소수는 0 쪽으로 자르고(`toIndex`), 구간의 무한은 clamp, 단일 조회(`At`)의
    범위 밖은 `nil`, 길이는 `[0, 2^26]` 밖이면 에러(`table.create` 한계, 실측).
  - 나머지는 `%` 가 아니라 `math.fmod`(+ 음수 보정) — `%` 는 |a| 가 2^53 을
    넘으면 틀립니다.
  - 예외: 계약 함수(`Get`/`NextIndex` …)는 알고리즘이 준 위치만 받는 자리라
    검사하지 않습니다. `Sum` 의 `base` 처럼 **값**으로 쓰는 숫자는 산술이라 대상 밖.
  - 테스트는 에러 **메시지와 사용자 줄을 같이** 단언합니다(메시지만 보면 수준이
    틀려도 통과 — 돌연변이로 확인).
  ⚠️ **삽입 위치는 유효 범위가 하나 넓습니다**(`1 .. n+1`). 조회용 clamp 로
  삽입까지 처리하면 "맨 뒤에 삽입" 이 표현 불가능해집니다(실제로 났던 버그).

- ⭐ **에러 규약** (2026-10-02, quad 탐사 — `papers/05`): 라이브러리 에러는
  **`Common.raise(msg)`** 로만 냅니다. 메시지는 `"Module: 설명"`. 손으로 센
  `error(msg, 2|3)` 은 **-O2 에서 틀렸습니다** — 로컬 헬퍼가 인라인돼 프레임이
  사라지는데 어느 것이 인라인될지는 컴파일러 휴리스틱이라(`NthElement` 는 틀리고
  같은 level 의 `Slice` 는 맞음), `-O1` 로만 돌던 테스트가 못 봤습니다. **라이브
  Roblox 는 -O2 가 기본**입니다. `raise` 는 스택을 걸어 **라이브러리 파일이 아닌 첫
  프레임**에서 던집니다 — 깊이·인라인과 무관하고, 콜백 안의 호출은 콜백 줄을
  가리킵니다. 비용은 에러 경로에만.
  - 모든 모듈은 로드 때 `Common.registerSource(debug.info(1, "s"))` 로 자기 파일을
    등록합니다(빠지면 그 모듈 줄을 가리킴). 되던지기만 `error(x, 0)`.
  - `check.sh` 가 지킵니다: `-O2` 로도 테스트를 돌리고, level 0 이 아닌 `error(` 와
    등록 누락을 grep 으로 막습니다. `spec.common` 이 **정확한 줄**을 단언합니다.
  - ⚠️ 테스트에서 줄 번호를 헬퍼 함수로 재지 마세요 — 그 헬퍼도 -O2 에서
    인라인됩니다(실제로 그랬음). `where = debug.info(1, "l") + 1` 을 그 자리에.
  - 반환 타입을 맞춰야 하는 자리는 `return Common.raise(...)` — Luau 는 `never`
    호출 뒤를 함수의 끝으로 보지 않습니다.

- **비교의 통화가 둘입니다**: 정렬·최대·최소는 불리언 `LessThan`
  (`table.sort` 가 받는 모양), 정렬된 구조에서의 탐색은 3방향 `Comparator`.
  둘 사이는 `Common.lessFrom` / `Common.compareFrom` 으로 건넙니다 — 비용이
  눈에 보이도록 자동 변환은 없습니다.

- **`table.move`/`table.create` 로 벌크 처리**, 가변인자 다수는 `table.pack`
  대신 `select` 루프. 근거는 아래 성능 절.

- **포매터는 stylua 입니다**(`stylua.toml`, `mise.toml` 에 2.5.2 고정).
  `./scripts/check.sh` 가 `--check` 로 게이트를 걸고, 어긋나면
  `stylua src tests` 로 맞추면 됩니다. 바이너리가 없는 환경에서는 건너뜁니다.
  **네임스페이스 `return { … }` 만 `-- stylua: ignore` 로 빼뒀습니다** —
  한 줄에 여럿 늘어놓는 편이 읽기에 낫기 때문입니다. 새 모듈도 같게 하세요
  (지시자는 **주석 전체가 정확히 `-- stylua: ignore`** 여야 먹습니다).
  ⚠️ **`(` 로 시작하는 문장을 쓰지 마세요** — `;(f :: T)(x)` 처럼요. 앞 문장이
  **`const` 선언이면 stylua 2.5.2 가 모호함을 가르는 `;` 를 지워** 파싱 에러가
  납니다(실측, 평범한 `local` 뒤에서는 앞줄 끝으로 옮겨 보존함). 지역 변수로
  받아 부르세요: `const f = x :: T; f(1)`. 에러가 나니 조용한 버그는 아니지만
  포맷 한 번에 멀쩡하던 파일이 깨집니다.

## ⭐ 성능은 1급 관심사

**[2026-09-21 사용자 확정]** *"이 프로젝트는 move 를 적극 쓰는걸 보면 알겠지만,
최적화를 엄청 신경 써서 만들고 있다."*

- **API 가 편의를 위해 기본 경로를 느리게 만들지 않습니다.** 편의 기능은 별도
  이름으로 옆에 둡니다. 예: `PushBack(v)` 는 고정 인자(비용 0)이고, 가변인자
  편의는 `PushBackMany(...)` 로 분리돼 있습니다 — 하나로 합치면 가장 흔한
  단일 추가가 8~13% 느려집니다(실측).
- **최적화 주장은 실측으로 뒷받침합니다.** 추측으로 "이게 빠를 것" 이라고
  쓰지 마세요.
- **벤치마크는 실제 호출 형태로 재세요.** 래퍼 클로저를 끼고 재면 상대 비용이
  희석됩니다 — 루프에서 네임스페이스 함수를 직접 호출해야 합니다(`local` 로
  받아 두는 것이 실제 쓰는 모양이면 그렇게). 노이즈를 피하려
  여러 번 재고 최소값을 씁니다.
- `table.move`/`table.create` 로 벌크 연산을 처리하고, 가변인자 다수 처리는
  `table.pack` 대신 `select` 루프를 씁니다(실측: 1.6~2.3배 빠름).
- **잰 숫자는 전부 `.claude/base/perf-measurements.md` 에 모읍니다.** 새로
  재면 거기에 추가하세요. 특히 알아둘 것 둘:
  **(a) 메타테이블이 붙어 있으면 `t[i]` 인덱싱이 1.59배 느려집니다**(빈
  메타테이블도 동일, `rawget` 로도 못 피함). 그래서 2026-10-01 에 **메타테이블을
  아예 없앴습니다**(질문 AB, perf 16절 — `Arr` 원소 작업 0.57~0.83배). 새
  컨테이너에도 메타테이블을 붙이지 마세요.
  **(b) `table.move`/`table.create` 가 원소 루프보다 빠릅니다** — 벌크로 할 수
  있는 일을 원소 루프로 쓰지 마세요.

## ⭐ `type function` 을 쓰지 않습니다 (2026-09-22 사용자 확정)

*"타입 함수는 문제가 너무 많기 때문에, 가급적 사용을 피할거야."* quad 이
같은 길을 먼저 갔고 부작용으로 대부분 폐기했습니다.

**이 저장소에서 `type function` 을 쓰던 코드는 전부 내렸습니다.** 지금
`src/` 는 **전부 `--!strict`** 이고 예외가 없습니다.

왜 쓰지 않는지, 세 함정:

1. `type function` 안에서 같은 파일의 바깥 로컬을 참조하면 **컴파일 실패**
2. `error()` 대신 `print()` + `types.never` 를 써야 진단이 노출됨
3. ⭐ 어떤 타입이 `type function` 을 **한 번 통과하면**(그냥 `return t` 라도)
   그 뒤 제네릭 `self` 메소드 체이닝이 **조용히 깨짐**

셋째가 결정적이었습니다 — 그때는 **체이닝이 공개 표면의 핵심**이었습니다
(`arr:Map():Filter():Sort()`). (2026-10-01 에 콜론 메소드를 없애 체이닝 자체가
사라졌지만, 나머지 두 함정과 제네릭 함수 전반의 위험은 그대로라 방침은
유지합니다.)

내려둔 실험 코드와 그 경위는 `.claude/research/type-function-experiment/`,
다시 열 때의 판단 재료는 `.claude/papers/03-tuple.md`.

## 테스트

전체 규칙과 파일 구조는 `.claude/base/architecture.md`의 "테스트: assert +
print" 절이 소스입니다 — 여기서 반복하지 않습니다. 요점만:

- **프레임워크 없음.** `assert(cond, "메시지")` + `print("PASS")`.
  실행은 `luau tests/run.luau`.
- **lune 을 쓰지 마세요.** 이 저장소는 순수 `luau` 로만 돕니다
  (`architecture.md`의 "런타임: 순수 luau" 절에 근거와 제약).
- 새 모듈을 구현하면 `tests/spec.<module>.luau` 를 만들고 `tests/run.luau`
  의 require 목록에도 넣으세요. **테스트 파일은 끝에서 값을 `return` 해야
  합니다** — 안 하면 `module must return a single value` 로 터집니다.
- **모든 경계 케이스를 테스트로 고정하세요.** 이 저장소는 범위를 벗어나도
  예외를 던지지 않고 조용히 clamp 하므로, 테스트가 없으면 "조용히 아무것도
  안 함" 과 "조용히 망가짐" 을 구분할 수 없습니다. 빈 것 / 한 개 / 뒤집힌
  구간 / 범위 초과 / 음수 인덱스를 매 절에 넣습니다.
- **눈으로 안 보이는 것은 대조로 잡으세요.** 이분 탐색은 선형 탐색과,
  `TreeSet` 의 병합 집합 연산은 `HashSet` 과, 힙은 정렬 결과와 무작위 입력
  수백 회로 대조합니다 — 실제로 그렇게 짜여 있습니다.
- ⚠️ **테스트 데이터가 우연히 맞아떨어지지 않게 하세요.** `TreeMap:Iter` 는
  키를 인덱스로 쓰는 버그가 있었는데, 테스트 키가 `1, 2, 3` 이라 인덱스와
  같아서 통과했습니다(키가 `10, 20` 이면 첫 원소에서 멈추고 문자열이면 크래시).
  키·값·위치가 서로 다른 값이 되게 고르세요(`10, 20, 30` / `"x", "y"`).
- **정확성이 까다로운 코드는 다른 눈으로 한 번 훑게 하세요.** 2026-09-30 에
  opus 리뷰어 셋(읽기 전용, "재현한 것만 보고")이 테스트가 놓친 버그를 열여덟
  개 찾아왔습니다 — 비동기 재진입, 무한대 키, NaN, 자기 자신과의 별칭 등.
  고칠 땐 **재현을 테스트로 먼저 쓰고** 그게 통과하게 고칩니다.
- ⭐ **리뷰는 "소진" 될 때까지 돕니다**(2026-09-30 사용자: *"소진 되었니?"*).
  고친 뒤 **새 리뷰어**가 수정분을 다시 보고, 재현되는 결함이 없다고 할 때
  멈춥니다. 같은 날 M1·M2·구멍 규약은 다섯 라운드가 걸렸습니다(20여 건 → 5 →
  버그 1+ → 버그 1 → 없음) — **수정이 새 결함을 만듭니다**(0 쪽 자르기가
  사톨로 치우침으로, 진입 검사가 비교 없는 호출의 회귀로). 첫 라운드는
  정확성·구멍/타입·검증 장치(돌연변이 시험)로 나눠 셋까지, 이후 라운드는 하나.
