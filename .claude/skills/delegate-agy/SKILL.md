# delegate-agy — Gemini 에게 다른 시선을 맡기기

quad 에서 먼저 만들었고(2026-10-02) 같은 날 사용자 요청으로 여기에 소급했습니다. 스크립트는
`.claude/tools/agy-delegate.sh`, agy 의 진입점은 `GEMINI.md`(레포 루트) 입니다.

## 왜 쓰나 (사용자, 2026-10-02)

sonnet 과 opus 는 Anthropic 의 베이스 모델을 교사로 두고 증류한 계열입니다. 그래서 성향과
선택 편향을 그대로 공유합니다. 다른 모델은 쓰지 않는 어휘("캐비엇", "팔")가 깨끗한 맥락에서도
따라옵니다. 이 레포에서는 이름 짓기처럼 객관성이 필요한 일에 sonnet 을 "외부자·내부자 시선"
으로 띄워 왔습니다. 시선을 지정하면 객관성이 조금 생기지만, **모델 단위의 경향성과 선택 편향은
좁혀지지 않습니다.**

리뷰가 소진돼 갈수록 문제를 보는 각도도 여러 개가 됩니다. 예전에는 문제가 많아 새 문제가
계속 나왔고, 그래서 이 점이 눈에 띄지 않았습니다. 지금은 같은 메커니즘의 문제를 공유하는
문항들이 나옵니다. 뿌리는 위에 있고 묶어서 볼 수 있지만, 조금씩 다른 문항도 있습니다. 이런
것은 여러 시각에서 합치거나 더 크게 보는 처리가 필요합니다.

Gemini 는 quad 에서 다른 시각을 이미 증명했습니다.

- sonnet·opus·fable 의 다패스 검증이 못 찾던 nil 구멍 문제를 대거 찾았습니다. 전부 사실은
  아니었지만, 제기한 문제 중에는 진짜가 있었습니다.
- Context 설계는 Gemini 의 제안을 거의 그대로 받았습니다.
- `Out` 이 없다는 것을 짚었고, 그 메커니즘도 받아들였습니다. diff-and-set 논의도 거기서
  시작했습니다.

사용자 평가는 이렇습니다.

- **장점**: 맥락 민감도가 높아 토큰 하나하나에 예민하고, 창의력이 높습니다. 정해진 틀을 넘어
  튀어올라 근본 원인을 파악하려 할 수 있습니다.
- **약점**: 지능 척도로는 Anthropic 모델을 이기지 못해 틀린 사고를 하기도 하고, 지어낸 말이
  섞일 수 있습니다.
- Anthropic 모델은 할루시네이션 통제가 높아 지시 이행을 잘합니다. 대신 버그를 찾으면 그걸
  고치려고 행동하고, 그 행동이 낳은 일을 다시 해결하는 식으로 일차원적으로 나아갑니다.
- 그래서 **판정은 가장 정확한 메인 세션이 합니다.**

stl-luau 에서 이 맥락은 직접 겹칩니다. 2026-10-02 의 에러 규약 리뷰는 여덟 라운드 동안
2 → 5 → 3 → 2 → 3 → 3 → 1 건을 냈습니다. 같은 틀 안에서 게이트와 테스트의 빈틈을 하나씩
메운 것이었고, M0 리뷰도 같은 모양이었습니다(위조가 라운드마다 한 겹씩 깊어짐).

## 언제 쓰나

- **근본 원인 찾기**: 열린 질문·리뷰 발견 여럿이 같은 메커니즘에서 나온 것 같을 때, 뿌리를
  위에서 찾게 합니다.
- **틀에서 튀어오르기**: Claude 계열 감사가 소진돼 가는 각도를 다른 틀로 보게 합니다. 설계
  결정(질문 AC·AD 같은 것)에 대한 바깥 의견도 여기에 듭니다.
- **버그 사냥**: 특히 이 레포의 중심인 **nil 구멍**과 `n` 불변식, 별칭(자기 자신과의 연산)
  문제를 봅니다. quad 에서 Gemini 가 가장 잘 찾은 종류입니다.
- **이름·어휘의 객관성**: sonnet 외부자·내부자 검토와 함께, 또는 대신 씁니다.

쓰지 말 것이 셋입니다.

- 결정을 맡기는 것.
- 메인 레포에 그대로 반영하는 것. 결과는 늘 메인이 검증하고, 메인이 직접 고칩니다.
- 결정 이력이 필요한 판정을 맥락 없이 맡기는 것. 필요한 이력은 프롬프트에 경로로 줍니다.

## 실행

1. **과제 프롬프트를 스크래치에 씁니다.** 한국어든 영어든 됩니다. 스크립트가 앞에 작업 환경
   규칙을 자동으로 붙입니다.
   - worktree 밖 쓰기 금지, git 커밋·push 등 금지
   - `ulimit` 를 붙인 실행, `check.sh` 의 exit code 로 판정
   - `AGY_REPORT.md` 에 한국어로 보고하고 실측과 추정을 가름
   - 기준 커밋은 직접 확인
   - 제안은 결정이 아님

   과제 쪽에는 다음을 적습니다.
   - **읽을 파일을 경로로** 줍니다. 진입점인 레포 루트의 `GEMINI.md` 는 agy 가 작업공간
     규칙으로 자동으로 싣습니다(agy 문서 `agy-customizations/docs/rules.md` — `.agents/rules/`
     는 안 실렸음, 2026-10-02 연결 확인).
   - **무엇에서 튀어오르기를 원하는지 명시**합니다. 예: "이 문항들을 개별 결함으로 보지 말고
     공통 뿌리를 위에서 찾아라."
   - **반증 가능한 근거**(파일:줄, 실행 출력)를 요구합니다.
   - quad 첫 과제의 교훈이 있습니다. 감사 문서를 입력으로 주면 틀이 그 분류에 고정됐습니다.
     **틀을 깨고 싶으면 앞선 리뷰의 분류를 주지 말고 원장(질문·코드)만 주세요.**

2. **백그라운드로 돌립니다.** Bash `run_in_background` 를 쓰고, 기본 모델은
   `gemini-3.8-flash-high` 입니다. 사용자 말로는 **pro 3.1 보다 flash 3.8 이 낫습니다.**

   ```
   .claude/tools/agy-delegate.sh run <이름> <프롬프트 파일> [--model M] [--timeout 3600]
   ```

   - 사용자 판단으로 agy 토큰 한도는 널널합니다. quad 에서 4분 돌린 것이 5시간 한도의 약 1%
     였습니다.
   - **동시에 최대 둘까지** 돌립니다. 이름만 다르면 됩니다.
   - worktree 는 **커밋된 HEAD** 에서 뜹니다. 과제가 볼 변경은 먼저 커밋합니다.

3. **끝나면 셋을 읽습니다.**
   - `/code/Projects/stl-luau-agy/<이름>/AGY_REPORT.md`
   - `.agy/guard.txt`: exit code, 메인 레포 변경 여부, worktree 변경 목록
   - 필요하면 `.agy/stdout.txt`

   worktree 에서 파일을 고쳤다면 `git -c safe.directory=<wt> -C <wt> diff` 로 봅니다.

4. **모든 주장을 메인이 직접 확인합니다.** quad 첫 과제에서는 다음이 틀렸습니다.
   - 기준 커밋을 입력 문서에서 옮겨 적었습니다.
   - 실측 결과를 거꾸로 인용했습니다.
   - 인용 위치가 반대였습니다.
   - 하지 않은 테스트를 "실측" 으로 표시했습니다.
   - 이미 닫힌 문항을 열린 것으로 셌습니다.

   확인된 발견만 규약대로 반영합니다(재현 테스트를 먼저 쓰고, 그다음 고침). 새 함수·이름·
   규약이면 `question.md` 문항으로 올립니다. 사용자에게 보고할 때는 **Gemini 의 발견과 메인의
   검증 결과를 갈라** 적습니다.

5. **원문을 남깁니다.** 쓸 만한 보고서는 `.claude/audit/agy/<날짜>-<이름>.md` 에 메인 검증을
   머리에 붙여 커밋합니다. quad 의 `agy-roots-2026-10-02.md` 모양입니다.

6. **다 읽었으면 지웁니다.** `.claude/tools/agy-delegate.sh remove <이름>` 으로 지우고, `list`
   로 남은 것을 봅니다.

## 격리

quad 의 실측(2026-10-02)을 그대로 따릅니다. 여기서 다른 것은 uid 와 경로입니다.

- `agy --sandbox` 는 cwd 밖 쓰기를 막지 **않습니다**. `unshare -m` 은 이 컨테이너에서 권한이
  없습니다.
- 그래서 agy 를 **uid 61001** 로 `setpriv` 실행합니다. quad 는 61000 을 씁니다. **uid 를 나눠**
  두 레포의 과제가 서로의 worktree 를 고칠 수 없게 합니다.
  - worktree 와 `.git/worktrees/<이름>` 만 그 uid 소유입니다.
  - 그래서 메인 작업 트리와 `.git/objects` 에는 쓸 수 없고, 커밋할 수 없습니다.
  - pre-push 훅이 push 도 거부합니다.
- HOME 은 `/code/Projects/stl-luau-agy/.home` 입니다. 실행마다 `/code/.gemini` 의 OAuth 를 새로
  복사합니다.
- PATH 앞에 mise 의 `luau`·`stylua` 설치 디렉터리를 붙입니다. 그래서 worktree 안에서
  `./scripts/check.sh` 가 돕니다.
- 실행 전후로 메인 레포의 HEAD 와 status 를 비교해 `guard.txt` 에 적습니다. 메인 세션이 그
  사이 작업했다면 "CHANGED" 가 뜨는 게 정상입니다.
