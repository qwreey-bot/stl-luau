## 1. Brand 와 Marker — 사용자가 짚은 것

### quad 는 어떻게 하나 (확인)

quad 는 정체성을 **두 층**으로 나눠 다룹니다.

- **런타임 = `Brand`**(`quad-types/src/init.luau:827-840`). 브랜드 하나가 **약한 키
  집합** 하나입니다(`setmetatable({}, { __mode = "k" })`).
  - 값은 생성될 때 `Register` 합니다. 값 쪽에는 필드를 하나도 심지 않습니다.
  - 술어는 `members[x] == true` 입니다. 구조를 보지 않으니 흉내 낸 테이블은 통과하지
    못합니다.
  - 한 값이 여러 브랜드에 들 수 있습니다(`Source` 는 `SourceBrand` 이면서
    `EpochBrand`).
- **타입 = `*Marker`**(`quad-types/src/init.luau:42-83`). 예:
  `StateMarker<T> = { read __quadState: true, read __quadStateValue: T }`.
  - quad 문서는 이것을 **조언층**이라고 부르고, 읽는 코드를 두지 말라고 적습니다.
  - 동기는 위조 방지가 아니라 **공변성**입니다. 입력 자리는 마커(`read` 라 공변),
    출력 자리는 전체형을 씁니다. 유니언 팔이 11개에서 5개로 줄고 체크 시간이
    4.96s 에서 3.41s 로 줄었습니다.
  - 위조를 막는 일은 런타임 Brand 의 몫입니다. 리터럴 위조를 막는 NEG 는 quad
    에 없습니다.
- 센티널(`None`)은 동결된 싱글턴과 `==` 비교입니다. 우리 `Optional.Absent` 와 같은
  결입니다.

**우리 타입 층은 이미 Marker 와 같은 기법입니다.** `read __arr__: true` 와
`ArrRead<T>` 가 그것이고, 리터럴 위조 NEG(`spikes/53`)는 우리 쪽에만 있습니다.
**더 나은 팬텀 기법은 찾지 못했습니다.**
- sentinel 테이블 키는 타입으로 쓸 수 없습니다. 인덱서를 둘 둘 수 없고, 인덱서 하나로는
  `{ n = 1 }` 리터럴이 통과합니다(A 실측).
- Luau 에는 라이브러리 코드에서 쓸 수 있는 명목 타입이 없습니다.

### 런타임 정체성을 바꿀까 — 세 방식 대조 (A·C 실측, 제가 Fut 분 추가)

| | 문자열 태그(현행) | 비공개 sentinel 키 | 약한 레지스트리(quad) |
|---|---|---|---|
| 위조 | 통과(경계 안의 한계) | **통과** — `pairs(진짜)` 로 키를 훔침, `table.clone` 이 키를 복사 | **막힘** |
| 등록 뒤 필드 변조(`n = 0/0`) | 술어가 모양으로 잡음 | 같음 | **못 잡음**(등록만 봄) |
| 원소 `t[i]` 읽기·쓰기 | 기준 | = | = |
| `Arr.Of` / `Clone(n=8)` 생성 | 기준 | ≈ | **~1.9x / 1.66x** |
| `Fut.Resolved` / `New` | 기준 | — | **1.24x / 1.16x** |
| `pairs` 에 보임 | `__arr__` | 테이블 키(직렬화에 더 나쁨) | 안 보임 |
| 라이브러리 사본 둘 | **호환** | 거부 | 거부 |
| `table.clone(진짜)` | Arr 로 인정 | 인정 | **거부** — 모든 복제 경로가 등록해야 함 |
| 타입으로 표현 | `read __arr__: true` | 불가 | 불가(팬텀 문자열을 그대로 둬야 함) |

**판단(제가 정함, 되돌리기 쉬움): 현행 유지.** 이유는 넷입니다.
- 레지스트리가 푸는 것은 **우리 위조 경계 밖의 위조**뿐입니다. 그 대가로 이 프로젝트의
  1급 관심사인 생성 성능을 1.66~1.9배 냅니다.
- quad 는 값 생성이 드문 UI 라이브러리라 이 세금이 문제가 되지 않습니다. 우리는
  `Arr.Map` 이 결과마다 새 컨테이너를 만듭니다.
- **`Fut` 만 따로** 바꾸는 안도 봤습니다. "`Pending` 위조가 영원히 대기한다" 는 한계를
  닫을 수 있지만, 생성이 1.16~1.24배 느려져 비용이 묻히지 않았습니다(A 는 묻힐 것으로
  추측했으나 제가 재 보니 아님).
- 사본이 둘일 때 문자열 태그는 서로 호환됩니다. pesde 로 두 버전이 설치돼도 `Fut.Chain`
  이 다른 사본의 `Fut` 를 받습니다. 레지스트리는 이걸 잃습니다.

A 가 짚은 작은 것 하나가 있습니다. `HashMap.FromTable` 이 `rawget(tbl, "__arr__")` 로
`Arr` 의 태그를 직접 읽어서, 태그 문자열이 모듈 경계를 넘습니다. 이건
**의도된 것**입니다. `HashMap` 은 의존을 한 방향으로 두려고 `Arr` 을 require 하지
않습니다(`HashMap.luau` `Keys` 주석). 정체성 방식을 바꿀 일이 없으니 그대로 둡니다.

## 2. ⭐ 에러 줄이 최적화 수준에 따라 갈렸음 (C → 고침)

**발견.** quad-error 머리 주석에 이런 문장이 있습니다: *"-O2 에서 로컬 직접 호출
함수는 인라인되어 태그가 걷기에서 사라진다"*. 이걸 보고 C 가 우리 테스트를 `-O2` 로
돌렸고, **실패했습니다**(제가 재현). 사용자 줄을 가리키지 못한 에러가 11건 이상이었습니다.
- `NthElement`·`PartialSort` 계열
- `Insert` 계열의 NaN
- `Sized`·`FromFunc`

같은 level 3 이라도 `Slice` 는 맞았습니다. 어느 헬퍼가 인라인될지는 컴파일러 휴리스틱입니다.
**라이브 Roblox 는 `-O2` 가 기본입니다**(Studio 는 `-O1`).

**처방.** 세 안을 견줬습니다.

| 안 | 내용 | 판단 |
|---|---|---|
| quad-error 태그 걷기 | 공개 함수에 레이어 태그를 달고 가장 가까운 태그 프레임을 찾음(199줄) | 태깅이 공개 함수마다 필요하고, quad 자신도 "로컬 함수에 달면 인라인으로 사라진다" 는 사용 규칙을 둠 |
| 헬퍼 깊이 0 규칙 | 공개 함수만 `error(msg, 2)`, 헬퍼는 메시지를 돌려줌 | 공개 함수끼리 서로 부르면 다시 틀림. 요령이라 곧 깨짐 |
| **소스 걷기**(채택) | 스택을 올라가며 **라이브러리 파일이 아닌 첫 프레임**에서 던짐 | 인라인으로 사라지는 프레임은 어차피 라이브러리 것이라 답이 같음. 태깅 대신 모듈마다 파일 등록 한 줄 |

**구현 → `conventions.md` "에러 규약"**:
- `Common.raise`
- 모든 모듈의 `registerSource` 한 줄
- `check.sh` 의 `-O2` 게이트와 grep 게이트
- `spec.common` 의 정확한 줄 단언 6가지
- 돌연변이 둘이 잡힘

덤으로 백로그였던 `TreeSet.Add` NaN 이 이제 사용자 줄을 가리킵니다. 테스트 쪽 줄 표시
헬퍼도 `-O2` 에서 인라인돼 틀렸는데, 바로 이 함정이라 규약에 적었습니다.

## 3. ⭐ 명시적 타입 인자는 콜백 주석도 없앤다 (B → 정정)

**발견.** quad `audit/type-recursive-issue-try-callback/REPORT.md` 11절이 단서였습니다.
`Arr.Map<<number>>(a, function(v) return v * 2 end)` 는 **0건**입니다. 우리 문서에는
"풀어주지 않는다" 고 적혀 있었지만, 그건 콜론 시절 실측이었습니다. 다음도 재현했습니다.
- `v.foo` 는 잡힙니다.
- 구멍이 있으면 `v` 가 `number?` 라 `v * 2` 가 잡힙니다.
- `spikes/52` 구멍도 같은 처방으로 막힙니다.

**같이 나온 한계(우리 문서에 없던 것)**: 분기마다 다른 값을 반환하면 첫 `return`
이 결과 타입을 굳힙니다. 처방은 `<<T, G?>>` 나 반환 주석입니다.

**처리**: `spikes/54`(POS 7 / NEG 3 / LIMIT 2), `typing-limits` 정정.

- **두 번째 체커(`luau-lsp analyze`)**: 지금 구성에서는 `luau-analyze` 와 결과가 같습니다.

    0건입니다.
  - 분기가 생겼을 때 알려 주는 경보로만 값이 있어 **백로그**로 둡니다.

- **공개 시그니처 스냅샷**(B 프로토타입 `snap.sh`): 모듈 키를 열거해 `luau-analyze`

  - 별칭 본문 변경은 못 봅니다. 그쪽은 음성 대조군이 지켜야 합니다.
  - **문서 사이트 단계**에서 문서 커버리지와 같이 검토합니다.

## 6. 인프라·자료구조·비동기 (C)

### 지금 반영한 것
- `-O2` 게이트와 에러 규약(2절).
- perf 문서에 **측정 모드** 명시와 모드별 메타테이블 세금(perf 18절).
  - 인터프리터에서는 1.60x 입니다.
  - **codegen 에서는 ~2.0x** 입니다. 메타테이블을 없앤 근거가 배포 모드에서 더 강해집니다.

### M3~M7 에서 쓸 메모
- **M5 `Deque`**: 첫 사용처가 우리 안에 있습니다. `Fut.luau` 의 `immediate` 트램펄린이
  손으로 짠 head/tail 큐입니다.
- **M7 `Fut` 타이머**(`Timeout`/`Retry`): quad 의 주입 op `setTimeout(fn, delay)` /
  `clearTimeout(handle)` 을 참고합니다(`debounce-throttle-plan.md`).
  - 순수 Luau 에는 이벤트 루프가 없어 기본값을 둘 수 없습니다. 그래서 **미주입이면 큰
    소리로 에러**를 냅니다(quad `NotInstalled`). 우리 provider 의 다른 필드처럼 조용히
    기본값을 쓰면 안 됩니다.
  - **취소를 먼저 정해야 합니다.** `Timeout` 은 `clearTimeout` 을 요구하는데, 우리 `Fut`
    은 지금 "취소 보류" 입니다.
  - 테스트는 quad mock 의 **가상 시계**(`advanceTime(dt)`, `(at, seq)` 순 발화) 모양을
    따릅니다.
  - 그 mock 은 만료 타이머를 매번 선형으로 스캔합니다(N²). `(at, seq)` 비교자를 쓰는
    `Heap` 의 자리입니다.
- **M6 `OrderedMap`**: quad 의 Slot 이 배열 + 역인덱스를 손으로 맞추다가 전체 교체가
  O(N²) 가 났습니다(N=5000 에서 2.06초). **삭제·삽입의 비용 모델을 먼저 문서에
  못박고** 만듭니다.
- **트램펄린 상한**: quad `Effect` 는 재진입 재실행을 미루면서 상한(10000)을 둡니다.
  우리 `immediate` 는 상한이 없어, 잡이 계속 잡을 넣으면 영원히 돕니다. 필요한지는
  미확인이고 M7 때 봅니다.
- **에러 스택 보존**: quad `Fallback.Traceback` 은 `xpcall` 로 에러 지점 스택을 남깁니다.
  우리 `Fut` 거절은 `pcall` 이라 스택이 사라집니다. M7 후보입니다(비용은 에러 경로뿐).

### 문서 사이트 단계에서
- 에러 문서는 층별 페이지에 "메시지 원문 / 언제 나는가 / 고치는 법" 을 둡니다.
  - 번호(`QuadNNNN`)는 지금 26곳이라 과합니다. **에러 자리가 50곳을 넘거나 문서를 만들 때
    다시 봅니다.**
  - 번호가 없으면 같은 주어에 메시지가 여럿일 때 앵커가 겹칩니다(quad 가 그 안을 기각한
    이유).
- 공개 표면과 문서 헤딩을 대조하는 커버리지 게이트를 둡니다. 소스는 모듈의
  `return { … }` 키를 런타임에 열거합니다.
- **문서 코드 펜스를 실제로 돌리는 게이트.** quad 는 이걸 수동으로 합니다. 우리는 순수
  Luau 라 ```` ```luau ```` 펜스를 뽑아 `luau` + `luau-analyze` 로 돌리기 쉽습니다.
- CHANGELOG(Keep a Changelog, BREAKING 에는 옮기는 법 한 줄)는 **첫 게시 전**에 둡니다.

### 성능 측정 방법
- quad 는 시간보다 **산술 카운터**(호출 수·스캔 길이)를 믿습니다. 우리도 `spec.arr`
  18절에서 비교 횟수로 이차 폭주를 잡고 있습니다.
- **복잡도 주장은 카운터로 고정한다** 는 습관을 새 컨테이너(Deque, Multiset)에도
  적용합니다.
- 노이즈 대책(최소값)은 우리 쪽이 더 엄격합니다.
