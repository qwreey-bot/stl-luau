# 페이퍼 — `Fut` (코루틴 래퍼)

**상태: ✅ 첫 판 구현됨 (2026-09-26).** `src/Fut.luau`, 테스트
`tests/spec.fut.luau`, 음성 대조군 `spikes/48`.

### 구현하며 정한 것 (되돌리기 쉬움 — `question.md` 에 모음)

- **`AndThen` 과 `Chain` 을 갈랐습니다.** 콜백이 값을 돌려주면 `AndThen`,
  `Fut` 을 돌려주면 `Chain`(펼침). JS `then` 처럼 합치면 "돌려준 게 Fut 이면
  펼친다" 를 Luau 타입으로 표현할 수 없습니다. Rust 의 `map`/`and_then`.
- **`Await` 는 `Fut` 이 만든 코루틴 안에서만 기다립니다.** luau CLI 는 메인
  스레드도 `isyieldable()` 이 참이고, 거기서 yield 하면 `pcall` 로도 못 잡는
  크래시가 납니다. 그래서 `Fut` 이 만든 코루틴을 약한 집합으로 기억합니다.
  ⚠️ **Roblox 에서는 이게 제약이 됩니다** — `task.spawn` 스레드에서도
  `Await` 하고 싶을 텐데 지금은 에러입니다. 스케줄러 provider 가 "이 환경에선
  아무 스레드나 기다려도 된다" 를 같이 알려주게 하면 풀립니다.
- **다중 반환은 팬텀 필드**(`_pack: (T...) -> ()`)로 들고 다닙니다. 3단
  체이닝·빈 팩까지 타입이 삽니다.
- **[2026-09-30] `All` 추가.** 결과는 **입력 순서대로 담은 `Arr<T>`**(끝난
  순서가 아니라), 실패는 **먼저 온 하나에서 바로**, 빈 목록은 빈 `Arr`.
  각 Fut 은 값 하나여야 합니다(목록 타입 `{ Fut<T> }` 이 다중 반환을 막음).
  `Fut → Arr → Optional` 단방향 의존이 생겼습니다.
- **[2026-09-30] provider 를 세 갈래로** — `schedule`/`canWait`/`resume`.
  Roblox 한 벌은 머리말에 예시로만(모듈은 환경에 중립).
- **[2026-09-30] opus 리뷰가 재현한 버그 일곱을 고쳤습니다** — 리스너 하나의
  에러가 나머지를 영원히 멈추게 하던 것, `Chain` 콜백의 `Await` 가 resolve 를
  부른 쪽 코루틴을 가로채던 것, 사슬 약 198단에서의 거짓 "C stack overflow",
  `Await` 가 이유 문자열에 위치를 덧붙이던 것, `All(Arr)` 가 런타임에 터지던
  것, 구멍 있는 목록에서 영원히 대기하던 것, `isOptional` 이 리터럴 Absent 를
  거부하던 것. 전부 `spec.fut` 11절 / `spec.optional` 에 회귀로 고정.
  즉시 스케줄러는 이제 **트램펄린**이고 `Async`/`AndThen`/`Chain` 의 본문
  시작도 거기 태웁니다(`New` 의 executor 만 즉시). 값은 `AndThen` 당 +0.35µs.
- **아직 뺀 것**: `Race`, 재시도(`Retry`/`OnRetry`), `Finally`, 처리 안 된
  실패 경고. 부르는 곳이 생기면 얹습니다.
- **가변 팩 명시적 타입 인자는 괄호**: `Fut.Rejected<<(number)>>(e)`.

아래는 착수 전 페이퍼 원문입니다.

> 사용자(2026-09-22): *"`Fut` 은 정확히는 간단한 코루틴 래퍼임. promise 같은
> 느낌인데, 이름이 짧아서 그것으로 택했어. 로블록스의 promise 라이브러리 같은
> 경우는 낡았는지라, 다시 쓰일 여지가 있어서 둔 부분이야."*

## 1. ⭐ 먼저 풀어야 할 것 — **스케줄러가 없습니다**

이게 나머지 모든 결정을 가릅니다.

이 저장소는 **순수 `luau` CLI** 로 돕니다(`base/architecture.md`). `coroutine.*`
은 있지만 **`task.spawn`/`task.defer` 도, 이벤트 루프도 없습니다.** 참고한
셋이 각각 다른 런타임을 전제합니다:

| 라이브러리 | 전제하는 런타임 |
|---|---|
| `qwreey/promise.lua` | luvit (libuv 이벤트 루프) |
| `evaera/roblox-lua-promise` | Roblox task 스케줄러 |
| `zserge/lua-promises` | 없음(동기 해결) |

evaera 가 스스로 밝히는 설계 목표 셋이 *"비동기 작업의 단위를 나타내는 객체",
"조합성", **"예측 가능한 타이밍"*** 인데, **셋째는 스케줄러 없이는 못 줍니다.**

### 갈림길

| 안 | 콜백이 언제 불리나 | 대가 |
|---|---|---|
| **A. 동기 해결** | `Resolve` 를 부른 그 자리에서 바로 | 재진입 위험. "때로는 동기, 때로는 비동기" 라는 고전적 함정 |
| **B. 스케줄러 주입** | 주입받은 것에 맡김 | 쓰는 쪽이 하나를 반드시 줘야 함 |
| **C. 안 만듦** | — | 이 저장소는 컨테이너 라이브러리로 남음 |

**→ [2026-09-22 사용자 결정] B 로 갑니다.** *"동의함. 해당 방법으로 놓고,
일반 luau 에서는 즉시실행 넣어주는거로 — quad 도 그런 부분에 있어서
provider 계층이 존재하고, 똑같이 따라가는 방법임."*

- **주입받습니다.** 비교자를 주입받는 것과 같은 결입니다.
- **순수 luau 기본값은 즉시 실행**(위 A). 그래서 아무것도 안 줘도 돕니다.
- **Roblox 에서는 `task.defer` 를 주면** 예측 가능한 타이밍을 얻습니다.
- 모양은 **quad 의 provider 계층을 따릅니다.**

```lua
local fut = Fut.New(function(resolve, reject) … end)          -- 즉시 실행
local fut = Fut.New(fn, { defer = task.defer })               -- Roblox
```

### 남은 것 — provider 를 어디까지 따라갈까

quad 은 `UseProvider` 로 **한 번 설정하고 그 뒤로는 안 넘기는** 층을
둡니다. `Fut.New` 마다 인자를 받는 것보다 그쪽이 쓰기 좋습니다.

⚠️ **다만 전역 상태입니다.** 이 저장소는 지금까지 전역이 하나도 없고
전부 인자로 받습니다(비교자, 해시, rng). 테스트가 결정적인 이유이기도
합니다.

**→ [사용자 답] provider 를 둡니다**(quad 과 같이). 전역 상태가 테스트를
비결정적으로 만들지 않도록, 테스트는 결정적 스케줄러를 provider 로 꽂아서
돌리는 모양이 될 것입니다.
절충으로 *"기본은 즉시 실행, `Fut.WithScheduler(sched)` 가 그 스케줄러를
쓰는 네임스페이스를 돌려줌"* 도 됩니다 — 전역 없이 한 번만 설정하는 효과.

## 2. 이 저장소에 둘 것인가

`Fut` 은 컨테이너가 아닙니다. 계약(`ListCore`/`MapCore`/`SetCore`) 어느 것도
만족하지 않고 `Algorithm` 과도 무관합니다. `Heap` 은 그래도 "값을 담는 것"
이지만 `Fut` 은 **제어 흐름**입니다.

- **같이 두는 쪽**: 이름이 짧고 `stl.Fut` 으로 바로 쓸 수 있습니다. 작은
  의존성 하나를 덜 답니다.
- **가르는 쪽**: 컨테이너만 쓰는 사람이 async 코드를 같이 받게 됩니다.
  pesde 워크스페이스로 `stl_fut` 을 따로 낼 수도 있습니다(다만 이 저장소는
  **단일 패키지 유지**로 결정돼 있습니다 — 2026-08-22).

## 3. 표면 초안 — `qwreey/promise.lua` 를 기준으로

사용자 본인의 라이브러리라 어휘를 그대로 가져가는 게 자연스럽습니다.
아래는 그 API 를 이 저장소의 네이밍 규약(PascalCase)으로 옮긴 것입니다.

| `promise.lua` | `Fut` 후보 | 비고 |
|---|---|---|
| `promise.new(func, ...)` | `Fut.New(fn, ...)` | 만들고 **즉시 실행** |
| `promise.async(func)` | `Fut.Async(fn)` | 부를 때마다 Fut 을 만드는 함수 |
| `promise.spawn(func, ...)` | `Fut.Spawn(fn, ...)` | 코루틴으로 실행 |
| `:andThen(f)` / `:catch(f)` | `:AndThen(f)` / `:Catch(f)` | |
| `:wait()` | `:Wait()` | 현재 코루틴을 멈추고 완료 시 재개 |
| `:await()` | `:Await()` | `Wait` + 결과. 실패하면 **에러** |
| `:awaitSafe()` | `:AwaitSafe()` | `Wait` + 결과. 실패해도 에러 안 냄 |
| `:isDone()` / `:isSucceed()` / `:isFailed()` | `:Done()` / `:Succeeded()` / `:Failed()` | 술어 |
| `:getResults()` / `:getResultsTable()` | `:Results()` / `:ResultsArr()` | 후자는 **`Arr<T>` 로 돌려줄 수 있습니다** |
| `:setRetry(n)` / `:whenRetry(f)` | `:Retry(n)` / `:OnRetry(f)` | 재시도. evaera 에는 없는 기능 |
| `promise.waitter` | `Fut.All(...)` | 여럿 기다리기 |

**`:ResultsArr()` 가 이 저장소 안에 두는 값어치입니다** — 결과를 `Arr<T>` 로
바로 돌려주면 컨테이너 API 와 이어집니다.

### 빠진 것 — 취소

`promise.lua` 에는 취소가 없고 evaera 에는 있습니다(전파까지). **취소는
설계를 눈에 띄게 복잡하게 만듭니다**(취소된 뒤의 `AndThen` 은 무엇이 되는가,
부모가 취소되면 자식은, 공유된 Fut 은).

**→ [2026-09-23 사용자 답] 잠정 보류.** *"루아우는 코루틴에 클로즈 해버리는게
존재해서 가능은 한 부분이지만, 애매한듯. 지금은 잠정 보류로 두고 나중에 확장
표면을 만드는게 되는 방향이면 그렇게 하는게 나아보임."*

- **가능은 합니다** — Luau 에 `coroutine.close` 가 있어 매달린 코루틴을
  닫을 수 있습니다.
- **지금 표면에는 넣지 않습니다.** 대신 **나중에 확장으로 얹을 수 있게**
  둡니다 — 기본 `Fut` 의 상태 표현이 "취소됨" 이라는 넷째 상태를 나중에
  받아들일 수 있는지만 설계할 때 확인합니다(지금 셋을 닫힌 유니온으로
  못박지 않기).

## 4. 타입 설계 — 이미 푼 문제와 같은 모양

`Fut<T>` 의 `AndThen` 은 `T` 를 `G` 로 바꿉니다. **`Arr<T>` 의 `Map` 과
글자 그대로 같은 모양**이라, 이미 실측한 규칙이 그대로 적용됩니다:

- 교집합(`&`)으로 전체형 (`setmetatable<>` 아님)
- 이름 붙은 함수 + `typeof` 나열
- 콜백 인자는 `Fut<T>` 를 언급하면 안 됨 → 필요하면 `FutView<T>`

**추가 실측이 필요한 것**: 다중 반환(`...T`)을 결과로 들고 다닐 때 타입이
버티는지. `promise.lua` 는 결과가 여러 개일 수 있습니다(`getResults` 가
언팩). `Arr` 의 `Flatmap` 에서 `...G` 를 다뤄봤으니 비슷하게 갈 듯하지만
**재봐야 합니다.**

**→ [2026-09-23 사용자 답] 다중 반환으로 갑니다.** *"된다 보긴 함. 이전에
링크 준 내 오래된 promise-lua 가 좀 잘못 구현된 감이 있지만, 여기서 아마
다중 반환을 잘 지원했던것 같아."* — `promise.lua` 는 결과를 테이블로
보관(`getResultsTable`)하고 언팩해서 돌려줍니다(`getResults`).

그래서 **착수 전 스파이크가 하나 늘었습니다**: `Fut<T...>` 의 가변 타입 팩이
`AndThen` 체이닝을 지나도 버티는지. tbox 가 *"new solver 는 가변 팩에 대해
infer 할 때 뒤따르는 인자를 오염시킨다"* 고 기록해둔 자리라
(`papers/03-tuple.md`), **팩을 함수 시그니처에 바로 두지 말고 한 겹
감싸야 할 수 있습니다** — tbox 의 팬텀 필드(`(T...) -> ()`) 방식이 후보입니다.
