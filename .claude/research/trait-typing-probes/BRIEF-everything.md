# 문제 설명 — 지금까지의 시도 전부 (종합하는 시선용)

먼저 `BRIEF-requirements.md`(요구사항)를 읽으세요. 그 위에서 오늘(2026-10-14) 사용자와 판 것들:

- **시제품 v2**(`../trait-v2/`, 연관 타입판): 컨테이너 타입에 `read __generics: { read Item: Inv<T> }`, 트레이트 시그니처엔
  표식 `UseGeneric<Item>`, `Fn` 의 출력에 타입 함수 `RewriteSig` 를 씌워 역추론되는 모양으로 바꿔 끼움, 등록 검사는 `ImplFor`.
  값에서 원소를 캐내므로 편한 길도 원소 검사됨. 대가: 컨테이너가 연관 타입을 적어야 함, 타입 함수 셋.
- **시제품 v3**(`../trait-v3/`, 제네릭 트레이트판): 트레이트가 제네릭 타입 `Stack<Self, T> = typeof(stackDef<<Self, T>>())`
  (팩토리 한 곳에서 이름 목록과 타입), 받는 쪽이 `T` 를 밝힘(`Stack.Of<<C, T>>(v)` — 주장, 검사 안 됨), 뭉텅이 구현은 제네릭
  함수로 검사, 편한 길은 any. 대가: 트레이트 객체의 타입(`Of`·`For`)을 트레이트마다 다시 적음.
- **실험 모음**: 이 폴더의 `README.md` 표 — 막힌 모양과 된 모양. 특히: 이름을 매개변수로 받는 `{ [Name]: T }` 는 인덱서가 됨,
  받는 쪽 타입 함수는 역추론이 안 됨, 공변 연관 타입은 넣는 쪽 검사가 빠짐, 자료 타입을 타입 함수로 만들면 그 종류의 제네릭
  함수가 깨짐, 등록 표는 주석 단 지역 변수여야 검사가 섬(인자·반환으로 넘기면 구현의 제네릭을 안 풂), 트레이트 객체 타입에
  `[string]: any` 인덱서를 섞으면 `Stack.Of<<…>>` 를 못 붙임.
- 사용자가 열어 둔 생각(결정 아님):
  - 기본 구현을 팩토리 안에 합치기: `Trait "Stack" (function<Self, T>() return { a = Default<<sig>>(완성된 함수), b = Fn<<sig>>() } end)`.
  - 그 팩토리를 구체 타입으로 불러 등록 모양을 얻기: `Impl(Stack<<Arr<T>, T>>()):For(TOKEN)` 같은 것.
  - `Trait` 이 제네릭을 받아 `Of`·`For` 의 타입을 대신 적어 주기.
  - `Trait.Impl(Stack):For(TOKEN)(impl)` 모양이 어색함(등록 표를 주석 단 지역으로 따로 적어야 해서).
  - 사용자 말: *"보이는 문제 뿌리는 Trait 자체에 제네릭이 없다는것 같아"*, *"Self 는 언어적으로 방법이 진짜 없는듯"*,
    *"타입 함수를 넣어 설계가 너무 산으로 가는 느낌"*, *"외부 확장 불가 문제는 원하던 방향이 아니긴함"*.
