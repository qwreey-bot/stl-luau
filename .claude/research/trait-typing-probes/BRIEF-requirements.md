# 문제 설명 — 요구사항만 (처음부터 생각하는 시선용)

Luau(Roblox 언어) 표준 라이브러리 `stl-luau` 의 **트레이트 시스템의 타입 설계**를 처음부터 생각해 주세요. 런타임은 정해져 있고
(아래), 막힌 곳은 **타입**(luau 0.742 의 새 솔버, `--!strict`)입니다.

## 정해진 것 (런타임 — 바꾸지 않음)

- 컨테이너(배열 `Arr`, 덱 `CircularDeque`·`LinkedDeque`, 맵·셋 …)는 **메타테이블 없는 평범한 테이블**이고, 연산은 모듈의
  네임스페이스 함수(`CircularDeque.PushBack(d, x)`)입니다. 값에는 종류를 가리키는 **타입 토큰**(`__type` 필드 — 종류마다
  하나인 얼린 테이블, 이름이 유일)이 있습니다.
- 트레이트는 함수 이름 목록을 가진 정의이고, 종류(토큰)마다 **구현 표**(`[함수 이름] = 함수`)를 등록합니다.
  - 필수 함수 / 기본 구현(트레이트가 자기 필수 함수로 짜 줌) / **뭉텅이 구현**(Rust 의 `impl<T: Deque> Stack for T` — "덱인
    모든 종류는 스택") / 종류를 콕 집은 구현이 뭉텅이를 덮음 / 뭉텅이끼리 겹치면 에러.
  - 등록은 런타임 호출이라 **타입 시스템은 "이 종류가 이 트레이트를 구현한다" 를 모릅니다**(Rust 의 impl 블록처럼 타입을
    고칠 수 없음).
- 종류를 모르는 코드의 경로:
  - **편한 길**: `Stack.Push(x, v)` — 트레이트 객체의 진입점(값의 토큰으로 구현 표를 찾아 부름, 시스템이 만듦).
  - **빠른 길**: 구현 표를 한 번 꺼내(`값으로` 또는 `토큰으로`) 루프에서 함수를 직접 부름.
- 바깥 사람(라이브러리 사용자)도 **새 트레이트와 새 컨테이너**를 같은 도구로 만들 수 있어야 합니다.
- 성능이 1급입니다 — 타입 층은 런타임 비용을 더하면 안 됩니다.

## 타입의 목표

1. 종류를 모르는 경로에서도 **원소 타입**(`T`, 리스트의 위치 타입, 맵의 키·값)이 호출하는 쪽에 흐를 것 — 예: 스택에서 꺼낸
   값이 `number?`, 틀린 원소를 넣으면 타입 에러.
2. 컨테이너를 만드는 쪽의 **등록 표가 트레이트 시그니처에 맞는지** 정적으로 검사될 것(빠진 함수, 틀린 서명).
3. 뭉텅이 구현의 몸통도 가능하면 검사될 것.
4. 바깥 사람이 새 트레이트(새 제네릭 — 예: 그래프의 `Node`)를 만들 때 **낯선 꼼수 없이** 할 수 있을 것.
5. DX: 트레이트를 정의하는 쪽, 구현하는 쪽, 쓰는 쪽 모두 반복이 적을 것.
