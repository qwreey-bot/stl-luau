# 숫자 토큰·배열 트레이트·시스템이 만드는 진입점 — 시제품 (2026-10-14)

사용자 설계: 토큰을 숫자로, 트레이트 객체의 배열 부분 `T[종류번호]` 가 완성 표(없으면 `false`), 완성 표는
`{ [함수번호] = f, 이름 = f }`, 함수 번호는 `T.Fn.이름`, 진입점은 시스템이 가변인자로 만들어 줌. `src` 는 그대로.

| 파일 | 무엇 |
|---|---|
| `TraitNum.luau` | 숫자 토큰, 배열 트레이트, 진입점 만들기(`Entry` 가변인자 / `Entry1`·`Entry2` 고정 인자 / `EntryByName`) |
| `Traits.luau` | `Deque` 하나를 여러 판으로: 숫자 토큰(손으로 쓴 진입점 — 이름 / 번호), 테이블 토큰(약한 키 있음·없음), 절충(테이블 토큰이 번호를 듦 + 정체성 확인), 테이블 토큰 + 시스템이 만든 진입점 |
| `bench.luau` | 같은 덱 함수를 부르는 값(`__type` 만 바꿈)으로 나란히 |
| `types-probe.luau` | 함수 번호를 타입에서 `"Push"` 로 보이게 하는 시도 — **안 됨**(아래) |

실행: `( ulimit -v 1048576; timeout 300 luau -O2 .claude/research/trait-numbered/bench.luau )`. 결과는 perf 53절.

- 타입: `표[Fn.Push]`(`Fn.Push: "Push"`)를 새 솔버가 필드 조회로 풀지 않습니다 — `Cannot add indexer to table 'Full'`.
  이름(`표.Push`)으로는 됩니다.
- ⚠️ 숫자 토큰의 위험(사용자 지적): 번호는 `require` 순서로 정해지니, 값을 직렬화해 옮기면(RemoteEvent 로 보낸 컨테이너,
  저장했다 읽은 값) 받는 쪽에서 **다른 종류로 조용히** 읽힐 수 있습니다. 테이블 토큰은 복사되면 정체성을 잃어 "모르는 종류"
  에러입니다.
