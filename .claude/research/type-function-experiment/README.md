# 리서치 보관 — `type function` 기반 튜플 실험

**여기 있는 코드는 `src/` 에서 내려온 것입니다. 돌지 않고, 검사되지 않고,
아무도 require 하지 않습니다.** 나중에 다시 볼 때를 위한 보관입니다.

> 사용자(2026-09-22): *"타입 함수는 문제가 너무 많기 때문에, 가급적 사용을
> 피할거야. … 지금은 지우고, 나중에 보기 위한 리서치 자료로 어딘가에
> 보관만 하자."*

## 무엇이었나

| 파일 | 무엇 |
|---|---|
| `Tuple.luau` (142줄) | Luau 의 실험적 `type function` 으로 튜플 **타입을 계산**하려던 시도. 런타임 `pack()` 은 돌았지만 모듈은 `return {}` 였고 `init.luau` 에서 export 된 적이 없습니다 |
| `TypeUtil.luau` (81줄) | 위가 쓰던 타입 수준 헬퍼 (`Merge` / `SetMetaProp` / `ExtractTagged` / `Tagged`) |

둘 다 `--!nocheck` 이었습니다 — 저장소에서 **유일하게 타입 검사에서 빠져
있던 코드**입니다. 이걸 내리면서 `src/` 전체가 `--!strict` 로 통일됐습니다.

## 왜 접었나

quad 이 같은 길을 먼저 갔고 **부작용으로 대부분 폐기**했습니다. 이미 기록돼
있던 함정 셋(`.claude/conventions.md`):

1. `type function` 안에서 같은 파일의 바깥 로컬을 참조하면 **컴파일 실패**
2. `error()` 대신 `print()` + `types.never` 를 써야 진단이 노출됨
3. ⭐ 어떤 타입이 `type function` 을 **한 번 통과하면**(그냥 `return t` 라도)
   그 뒤 제네릭 `self` 메소드 체이닝이 **조용히 깨짐**

**셋째가 이 저장소와 정면으로 부딪힙니다.** 여기는 체이닝이 공개 표면의
핵심입니다 — `arr:Map():Filter():Sort()`. 타입이 한 번이라도 그 관문을
지나면 그 뒤가 조용히 죽습니다.

## 다시 열게 된다면

`.claude/papers/03-tuple.md` 가 판단 재료를 들고 있습니다. 요점만:

- **튜플이 주는 것 중 `Arr` 로 안 되는 둘**(길이가 타입에 박힘, 원소마다
  타입이 다름)은 **전부 `type function` 이 필요했던 것**입니다. 그걸
  포기하면 남는 것은 `Arr` 가 이미 하는 일입니다.
- 대안 둘: tbox 식, 그리고 `select` 에 선택을 맡기는 식
  (`select(1, Tup:All())`). 후자는 타입 수준 길이 추적을 포기하는 대신
  **Lua 관례와 맞습니다** — 이 저장소가 구간 규약에서 이미 택한 태도입니다.
- **구체적인 호출부가 생기기 전에는 열지 않습니다.** 지금은 가정입니다.
