# DX 변호인 반박 (2라운드)

이번 라운드의 프로브는 `dx/m/a/b/` 의 `r1_D2.luau`, `r2/`, `r3/`, `TraitF.luau`, `TraitG.luau` 입니다(luau 0.742, `ulimit`+`timeout`).

## 인정하는 것

1. **인라인 B 의 같은 모듈 구멍은 진짜이고, 제 1라운드 답("라이브러리는 모듈을 나누니 괜찮다")은 약했습니다.**
   상대 말이 맞습니다. 바깥 사람의 트레이트는 정의와 쓰기가 한 스크립트에 있는 경우가 많습니다. 원인은 이제 밝혀졌습니다.
   덜 줄어든 `index<>` 가 서브타입 검사에서 `never` 로 떨어지는 것입니다. 그래서 "분리하면 괜찮다"는 우연에 기대는 말이었습니다.
   **인라인 B 를 추천에서 내립니다.**
2. **재정의 이름의 오타(`Fodl`)는 타입 계층에서 A 만 잡습니다.** 다만 "기본 구현으로 조용히 폴백한다"는 사실이 아닙니다.
   v8 런타임은 등록할 때 바로 던집니다. 모듈을 불러오는 순간, 어떤 호출보다 먼저입니다(`r3/run.luau`:
   `r3/run.luau:36: Trait: My.Arr4 gave Contians to ListRun, which ListRun does not have`). 조용하지 않고, 정적으로 잡히지 않을 뿐입니다.
3. **모드를 하드코딩하면(`Default("full", …)`) 에러가 구현자의 줄로 번집니다.** B' 에서도 똑같이 재현했습니다
   (`r2/c_hardmode.luau`: 정의 줄 + 등록 줄 54·55 + 쓰기 줄 57~59). 시끄럽기는 하지만 문구가 나쁩니다.
4. **C 는 꼴찌입니다.** 상대의 `c1`(이름 표류로 검사가 꺼짐)·`c3`(몸통 한 줄이 타입을 뒤집음)은 제 `p6`(형제 `ops` 를 받으면 풀리지 않음)과 같은 결론입니다.

## 반박

**"A 로 확정하고 상류가 고치면 B 로" — 기다릴 이유가 사라졌습니다.**
- 조건으로 든 #2608 은 구멍의 원인이 아니었습니다. 그리고 모드를 **밝혀 주면** 오늘 바로 닫힙니다(새 사실 1).
- 기다리는 동안의 비용은 바깥 사람이 냅니다. "작게 시작해 점점 늘림"이 지금 진행 중인 정책이라, 그 사이 `List` 가 자랄 때마다
  바깥 등록 표가 `missing field` 로 깨집니다. 전환할 때는 그 사이 쌓인 `Inherit` 줄을 걷어내야 합니다. 그러니 "기계적 변환"은
  우리 쪽 코드모드가 아니라 모든 바깥 사람이 손으로 하는 일입니다.

**B' 의 `<<"full">>` 도 아직 위험합니다. 잊으면 구멍이 조용히 다시 열립니다.**
- `Trait.Trait("List", listDef, listDef)` 처럼 타입 인자를 빼먹으면 같은 모듈의 반환 검사가 **0건**이 됩니다
  (`r2/b_no_inst.luau`: `NEG_has` 0건, 잡힌 것은 재정의 하나뿐).
- 정의자가 한 번 잊으면 그 트레이트를 쓰는 같은 모듈 전체가 조용합니다. 상대가 말하는 "조용한 구멍"을 B' 이 다시 만들 수 있는 자리입니다.

**대안 D3 — 모드를 타입 인자가 아니라 값으로 넘기면 제가 해 본 실수가 전부 시끄러워집니다.**

```lua
-- 기본 구현이 없는 트레이트(진짜 일곱 중 여섯): A 와 글자까지 같음 — index<> 없음, Inherit 없음
const Stack = Trait.Trait("Stack", function<Self, T>(of: (Self & Item<T>) | AnyToken)
	return { Push = Fn<<(stack: Self, item: T) -> Self>>(), Pop = Fn<<(stack: Self) -> T?>>() }
end)
-- 기본 구현이 있는 트레이트(List 하나): 정의 함수 하나 + 값으로 고른 모드 둘
local function listDef<M>(mode: M)
	return function<Self, E, I>(of: (Self & ItemIndexRead<E, I>) | AnyToken)
		return { Get = Fn<<…>>(), …, Contains = Default(mode, function(ops: List<Self, E, I>) … end) }
	end
end
const List = Trait.Trait("List", listDef(Trait.FULL), listDef(Trait.IMPL))   -- FULL: "full", IMPL: "impl" 상수
export type List<Self, E, I> = typeof(List.Of<<Self, E, I>>(nil :: any))
export type ListImpl<Self, E, I> = typeof(List.ImplOf<<Self, E, I>>(nil :: any))   -- 여섯에도 같이 둠(그땐 List 와 같음)
-- 등록: 필수만
const cdList: ListImpl<CircularDeque<A>, A, number> = { Get = …, FirstIndex = …, LastIndex = …, NextIndex = …, PrevIndex = … }
```

D3 에서 실측한 것(`TraitG.luau` + `r3/`):
- **같은 모듈에서 모든 NEG 를 잡습니다**(`r3/mod.luau`). 정의·등록·쓰기를 한 파일에 두어도 기본 구현 칸의 반환(`string ← boolean`),
  `Contains(...) + 1`, `Fold` 의 `U`, 원소를 못박은 재정의, 빠진 필수 칸이 전부 잡히고, canary 도 정상입니다.
- 정의자 실수가 모두 **시끄럽습니다**.

| 실수 | 결과 |
|---|---|
| 정의 함수를 부르지 않고 넘김(`listDef, listDef`) | 정의 줄과 정상 쓰기 줄에 에러(`r3/uncalled.luau`) |
| 모드를 맞바꿈 | 정상 등록·쓰기 줄에 에러(`r3/swap`) |
| `FULL` 을 두 번 | 필수만 적은 등록 표가 `missing fields`(`r3/twicefull`) — A 와 같은 시끄러운 실패 |
| 상수 대신 문자열 `"full"` | `index<…, string>` 이 되어 곳곳에 에러(`r3/lit.luau`) |

- 이름은 `Trait.Trait` 하나입니다. 인자 둘이면 한 겹, 셋이면 기본 구현이 있는 트레이트입니다. 오버로드는 인자 수로 갈려
  모호하지 않습니다(`r1_D2`, `r3`). 한 이름에 한 겹과 두 겹을 같이 받게 했던 1라운드의 시도는 `ambiguous` 였습니다.
- 런타임은 v8 그대로입니다(`r3/run.luau`: 기본 구현이 채워지고, 한 겹 트레이트가 돌고, 오타 등록은 에러).
- **대가**: 기본 구현이 있는 트레이트는 정의가 `Trait()` 밖의 이름 붙은 함수로 나갑니다. 사용자가 v5 에서 걸린 모양입니다. 그래도 v5 와는 다릅니다.
  해당하는 트레이트가 일곱 중 하나이고, `Mut` 이 없고, 같은 정의를 넘기는 자리가 `listDef(Trait.FULL)` 처럼 평범한 호출입니다.
  모드 하드코딩(`Default("full", …)`)이 구현자 줄로 번지는 것은 그대로 남습니다(인정 3). 하지만 조용하지는 않습니다.

**A 의 견고함 논거를 D3 에 대 보면:**
- "이름이 한 목록이라 표류가 없다": D3 도 기본 구현 이름은 정의 안에 한 번만 적습니다. 표류하는 C 와 다릅니다.
- "반환이 `any` 로 새는 구멍": D3 에는 없습니다(실측).
- 남는 차이는 재정의 오타 하나입니다. A 는 타입이 잡고, D3 는 등록할 때 런타임이 잡습니다.
  그 하나를 얻으려고 A 는 기본 구현 칸마다 런타임이 필요로 하지도 않는 `Inherit` 줄을 요구하고, `List` 가 자랄 때마다 바깥 구현을 깹니다.

**한 줄 등록(`X.For(X.ImplOf<<…>>)(토큰, { … })`)에 대해:**
검사가 되는 것은 좋은 소식입니다(새 사실 3). 그래도 기본 모양은 **주석 단 지역**으로 두기를 권합니다. 이유는 셋입니다.
- 에러 문구에 별칭 이름(`'ListImpl<…>'`)이 나옵니다.
- `For(Of<<…>>)(…)` 의 두 단계 호출은 처음 보는 사람이 따라 쓰기 어렵습니다.
- 증인과 표를 한 호출에 같이 넘기는 비슷한 모양은 0건이 되는 함정입니다(`freeze2`).

한 줄 등록은 아는 사람의 지름길로 문서에 덧붙이면 충분합니다. `table.freeze` 로 필드를 `read` 로 만드는 것은 D3 와 부딪히지 않습니다(직교).

## 수정된 최종 순위와 추천 모양 하나

**D3 > A > B'(`<<"full">>`) > B(인라인) > C**

- **D3 를 추천합니다.**
  - 기본 구현이 없으면 A 모양 한 겹이고, 있으면 정의 함수 + `Trait.Trait(이름, def(Trait.FULL), def(Trait.IMPL))` 입니다.
  - 등록은 `XImpl` 주석 단 지역에 필수 칸만 적습니다. `XImpl` 별칭은 모든 트레이트가 내보냅니다. 그래야 나중에 첫 기본 구현이 생겨도 등록한 쪽이 그대로입니다.
- **A 를 둘째로 올렸습니다.** 인라인 B 의 구멍을 인정했기 때문입니다.
- 남은 작은 일 둘:
  - 같은 모듈 구멍 재현과 B' 의 "타입 인자를 잊으면 조용함"을 상류 보고에 붙이는 것.
  - `types.luau` 같은 NEG 배터리에 "정의·쓰기 한 파일" 판을 넣어 D3 의 성질을 게이트로 지키는 것.
