# 시제품 v6 — v4 의 정의 모양 그대로, 빌린 참조는 트레이트가 고름 (2026-10-14)

v5(두 보기 `index<>` + 함수마다 `Mut`)를 보고 사용자: *"v5. 다시 DX가 나빠진다는게 좀 흠이네. Trait() 밖 까지 나가버리니까
뭔가뭔가가 되었음 mut 이란것도 조금 그렇게 보이는 느낌..? ArrRead 에 대해서는 Stack 자체가 구현 안되거나 하는 방향이 되거나
해도 되려나 … 타입을 맞추다가 DX가 나빠진것같아"*. 그래서 v4 에서 **정의하는 사람의 모양은 그대로** 두고 셋만 바꿨습니다.
v4·v5 는 그대로 둡니다.

| 바뀐 것 | 어떻게 | 정의자의 비용 |
|---|---|---|
| 빌린 읽기 참조 | 트레이트마다 팩토리의 `of` 한 자리에서 고름: 쓰는 함수가 있는 트레이트(Deque·Stack·Queue)는 `Item<T>`(불변) — 빌린 참조는 **그 트레이트를 아예 못 얻음**. 읽기만 하는 트레이트(List)는 `ItemIndexRead<E, I>`(공변) — 빌린 참조·넓혀 빌린 참조도 얻음 | 0(고르는 단어 하나) |
| 등록 | 트레이트 객체에서 `Stack.ImplFor(토큰, 표)`, `Stack.ImplWhere({ Deque }, 만드는 함수)`(사용자 제안). `ImplFor`·`ImplWhere` 는 트레이트의 함수 이름으로 못 씀 | — |
| 뭉텅이 몸통 | 제네릭 `<C, T>` 대신 탐침 타입 `Deque<A, B> → Stack<A, B>`(Gemini `tr3-body`) — 원소를 못박은 함수까지 잡힘. 런타임은 타입을 안 보니 그대로 | 오히려 줄어듦 |
| 에러 문구 | 진입점이 값을 못 찾을 때 진짜 토큰이면 "does not implement", 사본이면 "Trait.Restore it" — 둘을 가름 | — |

`types.luau` — 에러가 난 줄이 `-- NEG` 줄과 canary 와 정확히 같음(메인 실측). `check.luau` — `-O1`·`-O2` PASS.

## 그대로 남은 것 (v4 와 같음)

- **기본 구현 칸은 `Trait.Inherit`**(any 표식): 필수 칸에 넣어도 타입이 못 잡고(런타임이 등록 줄에서 잡음), 트레이트에 기본
  구현을 더하면 예전 등록 표가 "missing field" 로 깨짐. 두 보기는 v5 의 `index<>` 가 풀었지만 정의가 한 겹 바깥으로 나감 —
  `index<>` 없는 길은 Gemini `tr3-noindex` 가 찾는 중.
- 기본 구현 **빌더의 몸통**은 여전히 팩토리(제네릭) 안이라 몸통 결함에 노출 — 탐침 함수로 팩토리 밖에 두는 안(`tr3-body` 의 패턴 D)은
  안 들임.
- 편한 진입점은 `any`(서명을 한 곳에만 적고는 못 얻음 — Opus·Gemini 둘 다. Gemini 의 "원천 뒤집기"는 3-인자 트레이트의 `Of` 가 깨짐,
  `../../audit/agy/2026-10-14-tr3-entry.md`).
- 빌린 덱으로 `Front`·`Back` 같은 읽는 함수를 트레이트로 부를 수 없음(덱 트레이트를 통째로 못 얻음) — 모듈 함수를 직접
  (`CircularDeque.Front(r)`). 사용자가 낸 방향의 대가.
