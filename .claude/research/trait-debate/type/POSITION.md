# 입장문 — 타입 안전·견고함 변호인

## 순위: A(v6) > B(v8) > C

판정 기준은 "진단 0건인데 틀린 것의 수와 무게", "상류가 바뀔 때 무엇이 깨지나", "트레이트가 자랄 때의 안전".
프로브는 이 폴더(`x/y/trait-v6|v8/p*.luau`, `q*.luau`, `c*.luau`)에 있고 전부 `luau-analyze 0.742` 실측이다.
`trait-v6/types.luau`·`trait-v8/types.luau` 는 재현 확인(NEG 줄 = 에러 줄 + canary).

## 핵심 논거 셋

**1. B 는 정의와 쓰기가 한 파일이면 기본 구현 칸의 반환이 조용히 `any` 가 된다 (A 는 아니다).**
- `p2.luau`(B): 같은 파일에서 `local r2: string = tbl.Has(arr, 3)`(실제 boolean) 과 `tbl.Bad(...)` 가 **0건**.
  `q2.luau`: `local r2 = x.Contains("a",1); r2.foo.bar; r2 + 1` 도 0건 — 반환이 사실상 `any`.
  같은 코드를 A(`trait-v6/p2.luau`)에 넣으면 전부 잡힘. 필수 칸의 인자는 B 도 잡는다 — 빠지는 것은 기본 구현 칸의 **반환**.
- 모듈을 나눈 쓰기(`usemod.luau`: 직접·제네릭 함수 `D.P2<C,E>` 경유)에서는 B 도 전부 잡힌다. 즉 **파일 배치에 따라 검사가
  켜졌다 꺼지는** 결함이다. 후보 문서가 "원인 미확정"으로 적은 바로 그것. 이 라이브러리의 목표는 "누구나 자기 트레이트를 더한다"
  (CLAUDE.md "확장") — 사용자 트레이트는 대개 정의와 쓰기가 한 스크립트에 있다. 정확히 구멍이 열리는 쪽이다.
  원인은 상류(`index<{full,impl}, M>` + 표 리터럴 인자, #2608 계열)에 있고 우리는 고칠 수 없다.
- 반면 A 의 대가(`Inherit` 가 `any`)는 **런타임이 등록 줄에서 이미 잡는** 구멍(필수 칸에 Inherit → 등록 시 에러)이다.
  타입 구멍 중 "런타임 그물이 있는 것" 과 "그물이 없는 것(반환 any)"은 무게가 다르다. 호출하는 쪽의 반환이 `any` 라는 것은
  `Contains` 의 결과를 숫자로 써도 진단이 없다는 뜻이고, 런타임에선 틀린 값이 조용히 흐른다.

**2. 이름이 한 번만 적히는 A 는 오타·표류에 강하고, B·C 는 "선택 칸" 때문에 재정의 오타가 조용하다.**
- `p3.luau`: `Fodl = Arr.Fold`(오타) — A 는 **타입 에러**(Fold 칸 빠짐 + 모르는 키), B 는 **0건**(선택 칸 + 남는 필드 허용).
  B 에서 오타 난 재정의는 "기본 구현으로 조용히 폴백" = 속도(이 저장소 1급 관심사)가 소리 없이 사라진다.
  런타임 `unknownName` 이 등록 줄에서 잡아 주긴 하지만, 타입 계층은 못 본다.
- C 는 더하다. `c1.luau`: 기본 구현을 `stackDefaults` 에 더하고 `StackImpl` 의 선택 목록에 적는 것을 잊으면
  **서명이 틀린 재정의(`Count = pushBack`)도 0건**. 이름을 두 번 적는 구조 자체가 표류 지점이고, 표류하면 그 칸은 **검사가 꺼진다**
  (그것도 진단 없이). 트레이트 일곱 × 기본 구현 수십 개에서 이것은 시간 문제다.
- A 는 이름이 한 목록 → 표류 불가. 오히려 트레이트가 자라면 바깥 구현이 `missing field` 로 깨지는데, 이것은 **시끄러운 실패이고
  타입 전용**(런타임은 정상)이다. 조용한 구멍보다 시끄러운 마찰이 견고하다. 완화: 기본 구현 추가는 마이너에서 미루거나 알린다.

**3. 솔버·타입 함수 의존도는 A < B ≈ C 이고, 갈아타기는 A→B 가 기계적이다.**
- A 는 v4 에서 오래 시험한 `typeof(Of<<…>>)` 뿐. B 는 거기에 `index<…, M>` 두 개 + 오버로드 교집합 인자
  (`((mode:"full")->F) & ((mode:"impl")->G)`)에 얹힌다. `Default("full", …)`처럼 모드를 박으면 에러가 정의자의 줄이 아니라
  **구현자의 등록 줄**에 `Property 'string' does not exist on type '{full…, impl…}'` 로 번진다(`p1.luau`) — 상류 한 번 바뀌면
  전 구현자에게 퍼지는 모양. 사용자 지침(`type function` 주의: 테스트 어렵고 버그 많음)이 내장이라고 면제되지는 않는다:
  `index<>` 는 같은 타입 함수 경로다.
- C 는 타입 함수는 없지만 **본문 추론에 기댄다**. `c3.luau`: 기본 구현 몸통의 `ops.Get(l, ops.First(l) :: I) ~= nil` 한 줄 때문에
  `typeof(defaults<<S,E,I>>(…))` 의 인스턴스화가 통째로 풀려 정상 호출이 `Expected 'Self', got 'string'` 로 거절됨.
  몸통을 `return true` 로 바꾸면 통과(`c14`). 몸통 한 줄이 타입을 뒤집는다 = 시험하기 어렵다. A·B 는 같은 몸통에서 영향 없음(`q1.luau`).
  게다가 C 는 런타임 시제품이 없고(두 표를 받는 `Trait.Trait` 미구현), 프로브의 기본 구현은 `ops` 를 받지 않아 실제 `List`(형제 기본 구현
  `Contains → IndexOf`)를 표현 못 한다 — 표현하려면 위 취약한 길로 간다.
- 갈아타기: B 의 정의 = A 의 정의 + 함수 한 겹 + `Default(mode, …)`, 등록 = `Inherit` 삭제. 기계적 변환이다. 그러니 **지금 A 로 확정하고
  상류가 #2608 을 고치면(그리고 같은 파일 구멍이 사라지면) 코드모드로 B 로** — 반대로 B 로 시작해 구멍이 상류에 있다고 밝혀지면 모든 구현자가 영향.

## 규모 실측 (낙관 방지)
`scale7/scale20.luau`(트레이트 7·20개 × 필수 6 × 기본 구현 6 × 구현 8): 분석 시간 A 0.19–0.21s, B 0.06–0.16s. **규모/속도는 차이 없음**.
B 가 틀리는 것은 규모가 아니라 위 구멍이다. 필수 칸 누락·재정의 서명 틀림은 A·B 모두 잡는다(`mut7.luau`: 틀린 `D2` 서명 잡힘).

## 예상 반론과 답
- "A 는 `Inherit` 로 DX 가 나쁘다/트레이트가 자라면 바깥이 깨진다." → 시끄럽고 타입 전용·런타임 무영향. B 의 대가는 조용한 반환 `any`.
  게다가 `Inherit` 오기는 런타임이 잡는다. DX 는 사용자가 명시적으로 판단할 몫이고, 나는 "조용한 구멍 수"로만 말한다.
- "B 구멍은 같은 파일에서만이고 라이브러리는 모듈 분리다." → 라이브러리 내부 테스트·사용자 트레이트가 정확히 그 배치. 원인 미확정인
  채로 "분리하면 괜찮다"는 우연에 기대는 것. (라이브러리 파일 안의 진입점·`spec` 이 같은 파일에서 `Of` 를 쓰면 열린다.)
- "C 는 타입 함수 0 이라 가장 견고하다." → 이름을 두 번 적는 표류(`c1`)와 몸통 추론 의존(`c3`)이 조용/불안정. 타입 함수 유무만으로 견고함이 정해지지 않는다.
- "A 의 필수 칸 `Inherit` 는 any." → 런타임이 등록 때 에러. B 의 반환 `any` 에는 그런 그물이 없다.

## 변형 D 제안 (프로브 미완 — 방향만)
A 를 채택하되 (1) 정의 모양을 B 로 코드모드 가능한 꼴로 유지(`Default` 에 `mode` 자리를 예약하지는 않음), (2) `Inherit` 오기를 막기 위해
`spec.contracts` 에 "필수 칸에 Inherit 없음" 대신 런타임 그물을 이미 쓰는 것을 문서화, (3) 새 기본 구현 추가를 "바깥 구현이 깨지는 변경"으로
릴리스 노트 규칙화, (4) 상류 #2608 이 닫히고 B 의 `q2/p2` 가 잡히면 전환. 상류에 B 의 같은 파일 구멍 재현(`q1.luau`)을 보고하는 것은 어느 쪽이든 권장.
